# SDD-016: GitLab, календарь и рекомендации стажёру

Статус: проектное предложение. Решения дополняют SDD-015. Интеграции ещё не развёрнуты.

## GitLab

Self-Managed GitLab и gitlab-integration запускаются отдельными контейнерами. GitLab хранит репозитории и права. Интеграция хранит привязки аккаунтов, подписки и состояние доставки. Бобби получает MCP tools/list и выбирает инструменты по смыслу запроса. Первая версия читает доступные пользователю MR, состояние ревью, approvals и pipeline.

Пользователь привязывает собственный GitLab через OAuth Authorization Code с PKCE и read_api. Привязка связывает проверенный sub Бобби с ID GitLab, полученным от GitLab. Для MVP с общей демосессией допускаются отдельные тестовые аккаунты, личные OAuth-привязки включаются после появления индивидуального входа. Токены хранятся зашифрованными на стороне интеграции. При отключении аккаунта подписки останавливаются. Изменения в GitLab выносятся на следующий этап с отдельным согласием на запись и подтверждением конкретного действия.

Для напоминаний начать с опроса открытых MR пользователя. Использовать состояние approval rules, исключать черновики и закрытые MR. Если API не подтверждает обязательность approvals, описывать только наблюдаемое состояние ревью. При росте нагрузки webhook инициирует повторную проверку с правами получателя. Дедупликация по получателю, проекту, MR и состоянию, доставка через общий канал уведомлений Бобби.

## Google Calendar

calendar-integration работает отдельным контейнером с OAuth и MCP. Стажёр даёт read-only доступ к событиям своего календаря, сервис ограничивает чтение выбранными календарями и диапазоном дат. Для ментора каталог команд определяет связанного наставника, а доступность читается через FreeBusy из явно расшаренного календаря. Если sharing не настроен, доступность неизвестна. Для демо использовать отдельные учебные календари. Подробности общих встреч берутся из календаря стажёра. Напоминания учитывают часовой пояс, переносы и отмены. Для фоновой доставки требуется отдельное согласие на длительный доступ и возможность отключить подписку.

## Вопросы и рекомендации

Доступы проверяет сервис прав, состав и роль даёт каталог команд. Синтетические навыки помечаются как демоданные и привязываются к роли, человеку и источнику. Рекомендации строятся на подтверждённых требованиях задач Jira, доступных материалах Авито и разрешённых MR GitLab. При недостатке данных Бобби предлагает уточнить опыт или выбрать тему, без вывода о пробелах в навыках. Ответ содержит 1–3 действия, объяснение связи с ролью или задачей и ссылки на источники. Данные сотрудников выдаются в пределах членства и разрешённых полей. OAuth-токены остаются в сервисах и не попадают в контекст модели.

## Порядок и приёмка

1. Индивидуальная идентичность, GitLab OAuth и MCP только для чтения, затем напоминание о зависшем ревью.
2. Calendar OAuth, календарь стажёра и доступность ментора. Добавить уведомления о ближайших встречах.
3. Рекомендации по одной роли на примере учебных данных и расширение набора ролей после проверки.

Приёмка проверяет изоляцию двух пользователей и закрытого проекта, отзыв OAuth, повтор события без повторного уведомления, перенос встречи, отказ в доступе к деталям календаря ментора и рекомендации с источниками при наличии и отсутствии данных. MCP-контракты и ограничения действуют независимо от выбранной модели.

## Уточнения перед реализацией

- GitLab разворачивается локально в Docker. Демо-проект основан на нашем сервисе каталога команд. Для него готовятся учебные коммиты и merge requests с разными состояниями ревью.
- Первая версия MCP поддерживает дерево репозитория, чтение файла по ветке, тегу или SHA, историю коммитов и просмотр diff коммита и merge request. Каталог расширяемый. Новые инструменты используют ту же проверку прав пользователя.
- Два учебных календаря: «Онбординг стажёра» и «Доступность ментора». Период с 10 ноября по 9 декабря 2026 включительно, по будням с 09:00 до 18:00, Europe/Moscow. Содержание опирается на чек-листы и документацию проекта. Время событий учебное.
- Первый профиль для рекомендаций — стажёр-бэкендер команды платформы разработки. Бобби использует все релевантные задачи Jira, видимые пользователю, в том числе задачи коллег и завершённые. Для проверки навыка формулирует задание и критерии по документации Авито и подтверждённой практике команды.
