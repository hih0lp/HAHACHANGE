# SDD-043: точный срок тестовой Jira-задачи

## Сценарий

Для проверки минутных пингов нужна одна незавершённая задача первого стажёра со сроком через 15 минут после её создания. Обычное поле Jira `due_date` содержит только календарную дату и в напоминаниях трактуется как начало следующего дня в настроенном часовом поясе, поэтому не подходит для такой проверки.

## Данные и поведение

- Мок Jira принимает необязательное `due_at` в формате RFC 3339 с часовым смещением. Оно хранится только в редактируемом `fixtures/mock/jira.json`. Некорректное время делает весь снимок недействительным с явной ошибкой; отсутствие `due_at` сохраняет прежнюю семантику `due_date`.
- MCP карточка и список возвращают точное время, а read-only поиск для напоминаний включает его вместе с задачей и исполнителем. Бобби показывает точный срок из MCP; напоминания используют `due_at` с приоритетом перед `due_date`.
- Тестовая задача принадлежит первому стажёру по `assignee_account_id` из JSON. Для дедлайна в окне 15 минут сканер создаёт карточку ему за 10 минут и наставнику его команды за 5 минут. Имя задачи, ID исполнителя и точное время не зашиты в коде. Дубликаты исключает существующий ключ БД `(recipient_id, kind, issue_key, due_at)`.
- После срока задача остаётся в учебном JSON как исторический пример; новых уведомлений по ней не создаётся.

## Проверка

Тесты проверяют допустимый и ошибочный RFC 3339, поиск задачи без `due_date`, границы минутных окон и прежний расчёт для задач с одной датой. На `bobby-mocks` создать одну задачу с абсолютным `due_at` через 15 минут от момента записи, проверить карточку Jira и ответы `GET /v1/deadline-notifications` для первого стажёра и наставника в соответствующие окна. Наличие завершённого окна подтверждать фактическими ответами, а не только состоянием контейнеров.
