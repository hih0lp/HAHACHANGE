# SDD-043: точный срок тестовой Jira-задачи

## Сценарий

Для проверки минутных пингов нужна одна незавершённая задача первого стажёра со сроком через 15 минут после её создания. Обычное поле Jira `due_date` содержит только календарную дату и в напоминаниях трактуется как начало следующего дня в настроенном часовом поясе, поэтому не подходит для такой проверки.

## Данные и поведение

- Мок Jira принимает необязательное `due_at` в формате RFC 3339 с часовым смещением. Оно хранится только в редактируемом `fixtures/mock/jira.json`. Некорректное время делает весь снимок недействительным с явной ошибкой; отсутствие `due_at` сохраняет прежнюю семантику `due_date`.
- MCP карточка и список возвращают точное время, а read-only поиск для напоминаний включает его вместе с задачей и исполнителем. Бобби показывает точный срок из MCP; напоминания используют `due_at` с приоритетом перед `due_date`.
- Тестовая задача принадлежит первому стажёру по `assignee_account_id` из JSON. Для дедлайна в окне 15 минут сканер создаёт карточку ему за 10 минут и наставнику его команды за 5 минут. Имя задачи, ID исполнителя и точное время не зашиты в коде. Дубликаты исключает существующий ключ БД `(recipient_id, kind, issue_key, due_at)`.
- После срока задача остаётся в учебном JSON как исторический пример; новых уведомлений по ней не создаётся.
- «Мои задачи» загружает ближайшие Jira-дедлайны через `GET /v1/tasks/jira`. Личность определяется командным токеном. Каждый стажёр получает только свои незавершённые задачи в часовом окне `REMINDER_HOURS_BEFORE`. Наставник получает задачи стажёров тех команд, в которых каталог указывает его наставником. Маршрут использует тот же разбор дат, что и `GET /v1/reminders`. Старый маршрут сохраняет прежнее поведение для своих клиентов.
- Чат получает сохранённые карточки через `/v1/deadline-notifications/ws`. После открытия сокета клиент передаёт командный токен и API-ключ первым сообщением. Сервер отправляет снимок для подтверждённого профиля при подключении и после каждого прохода сканера. При обрыве браузер переподключается и снова получает снимок. Закрытые карточки остаются скрытыми при переподключении и перезагрузке. HTTP-маршрут сохраняется для совместимости.

## Проверка

Проверено тестами Go: каждый стажёр получает свои задачи, наставник получает обе, а подмена cookie демо-роли не меняет выборку токена. Браузерная проверка подтверждает получение карточки по WebSocket, появление нового срока после обрыва соединения и сохранение закрытых карточек после переподключения и перезагрузки.

Тесты проверяют допустимый и ошибочный RFC 3339, поиск задачи без `due_date`, границы минутных окон и прежний расчёт для задач с одной датой. На `bobby-mocks` создать одну задачу с абсолютным `due_at` через 15 минут от момента записи, проверить карточку Jira и ответы `GET /v1/deadline-notifications` для первого стажёра и наставника в соответствующие окна. Наличие завершённого окна подтверждать фактическими ответами, а не только состоянием контейнеров.

На тестовом сервере создана одна задача `SCRUM-8` для первого стажёра по существующему `assignee_account_id`. При записи срок был установлен на `2026-11-14T22:36:37+03:00`, через 15 минут после создания; read-only карточка мока вернула тот же ключ и точное время. Снимок добавлен в Git для воспроизводимости после срока.

Проверка БД тестового стенда в соответствующих окнах подтвердила две записи для `SCRUM-8`: `intern/intern_deadline` за 10 минут и `approver/mentor_deadline` за 5 минут до указанного срока. Прямое чтение БД проверяет работу сканера; отображение уведомлений в браузере отдельно не автоматизировано.

## Уведомление в чате

Активное напоминание показывается одной красной карточкой над областью прокрутки чата. Кнопка «Закрыть уведомление» сохраняет ID закрытой карточки для текущей роли в браузере. Повторный опрос API и перезагрузка страницы не возвращают её. Новый срок создаёт уведомление с новым ID.
