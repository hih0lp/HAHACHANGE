# 047 — Общий тестовый календарь двух стажёров

Календарный мок проверяет токен через `/v1/me` сервиса команды и разрешает чтение через MCP только ID из `CALENDAR_DEMO_SUBJECT`. Переменная принимает один ID или список через запятую. Пробелы по краям ID игнорируются. Для общего календаря двух стажёров укажите `CALENDAR_DEMO_SUBJECT=intern,intern2`. Пустой список считается ошибкой конфигурации.

Эта настройка применяется к чтению событий и занятости. Административная запись календаря по-прежнему требует отдельного токена. На тестовом стенде до изменения обе роли получали токен, а `GET /v1/calendar/reminders` возвращал 200 для первого стажёра и 503 для второго из-за отказа календарного MCP.

Проверка кода: `go test ./cmd/mock-calendar ./cmd/server` прошёл. При выкладке проверяйте запрос событий отдельно для каждой роли с её токеном.

Обработчик календарного мока создаётся отдельно от запуска процесса, чтобы проверять HTTP и MCP через тестовый сервер. Приёмочные проверки покрывают доступ по JWT, отказ без токена и для чужого пользователя, чтение событий наставника и компании, занятость без названий встреч, отменённые события, неверный период и состояние `/health` при повреждённом JSON. Формат маршрутов и ответов остаётся прежним.

Инициализация из переменных окружения отделена от `main()`. Тест с отдельной схемой PostgreSQL проверяет отказ при неверной конфигурации и повреждённом исходном JSON, затем сохранение исходного снимка и чтение его через HTTP. Закрытие соединения с базой выполняется при ошибке и при штатном завершении процесса.

На активном тестовом стенде `bobby-local` после обновления календарного контейнера `GET /v1/calendar/reminders` вернул 200 и `calendar#events` для каждого стажёра. В проверенном интервале событий не было. Для роли наставника маршрут сохранил прежний результат 503.
