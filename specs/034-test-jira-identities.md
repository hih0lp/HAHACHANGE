# SDD-034: Jira accountId для трёх тестовых ролей

Тестовый чат имеет роли `intern` (стажёр 1), `intern2` (стажёр 2) и `mentor` (наставник). Роль чата `mentor` входит в сервис команды под ID `approver`. Сервис команды получает сопоставление своих ID с Jira `accountId` из JSON-переменной `TEAM_JIRA_ACCOUNTS_JSON` в отдельном тестовом `.env`; идентификаторы ниже относятся только к моковым пользователям. Локальный Compose содержит такое же сопоставление для своего снимка.

Актуальный снимок `fixtures/mock/jira.json` использует отдельные демонстрационные `accountId` для трёх ролей:

| Пользователь сервиса команды | Тестовый Jira accountId | Задачи в текущем снимке |
| --- | --- | --- |
| `intern` | `demo-intern` | SCRUM-6, SCRUM-7, SCRUM-8, SCRUM-9 |
| `intern2` | `demo-intern2` | SCRUM-4, SCRUM-5, SCRUM-10 |
| `approver` | `demo-approver` | Нет |

Тестовая конфигурация:

```dotenv
TEAM_JIRA_ACCOUNTS_JSON={"intern":"demo-intern","intern2":"demo-intern2","approver":"demo-approver"}
```

Эти mock ID не выдаются за реальные Jira-аккаунты. Перед изменением переменной на старом тестовом стенде необходимо заменить его записываемый Jira JSON на актуальный снимок из `main` и сверить назначения. Затем пересоздать только тестовый контейнер `team-access`, чтобы он обновил профили в собственной БД; API и mock Jira читают их через существующий MCP. Списки личных задач должны содержать 4 и 3 задачи соответственно, без пересечения. Календарная авторизация этой правкой не меняется.

Проверка: получить профиль каждой из трёх тестовых ролей через сервис команды, проверить три разных ID и вызвать личный список задач. Рабочий `.env` и рабочий стек не меняются.

Старый снимок тестового стенда содержал 8 задач и два назначения на прежний `accountId` первого стажёра. Он несовместим с таблицей выше. Проверка после обновления: прочитать текущий JSON из контейнера mock Jira, получить профили через `/v1/me` и вызвать личный MCP-список для обеих ролей.

Проверка `bobby-mocks` 16 ноября 2026 года: записываемый Jira JSON обновлён до снимка из `main` с 12 задачами, тестовый `.env` обновлён с резервной копией, пересоздан только `team-access`. `/v1/me` вернул `demo-intern` и `demo-intern2`; `jira_list_assigned_issues` по JWT каждого стажёра вернул соответственно 4 и 3 задачи. Рабочий `.env` в Git не добавлялся.
