# SDD-038: понятное подтверждение формы доступа

Встроенная форма чата показывала сырой JSON с `resource_id`, `capability` и `reason` после нажатия «Проверить заявку». Это внутренний формат запроса, который пользователю видеть не нужно. Экран подтверждения теперь показывает только краткий запрос на подтверждение и кнопку отправки. Значения остаются в памяти текущей формы и передаются серверу лишь после отдельного подтверждения пользователя. После успешного ответа сервера показывается `Заявка успешно отправлена!`.

Повторная отправка для уже ожидающей заявки раньше возвращала красную общую ошибку `form could not be submitted: verify fields and access`. Бобби сначала выполняет прежнюю отправку через MCP, сохраняя идемпотентный повтор с тем же ключом. Только если отправка не удалась, он запрашивает состояние доступа для выбранного ресурса и права. При состоянии `pending` форма показывает понятное `Заявка на этот доступ уже отправлена и ожидает решения.`; при состоянии `granted` показывает, что доступ уже есть. Эти ответы HTTP 409 отображаются как обычное уведомление без красной подсветки. Остальные ошибки остаются явными, но без внутреннего JSON или английского текста в интерфейсе. Проверка не заменяет серверную валидацию и уникальность записей.

В тестовой базе предыдущая сквозная проверка агента создала ожидающую заявку для стажёра 1 на учебный Jira-ресурс. Именно она мешала последующей повторной отправке того же доступа. После подтверждения причины эта собственная тестовая заявка и связанные с ней тестовые аудит и outbox удаляются из изолированной базы; чужие записи не затрагиваются. Рабочий стенд не меняется.

Проверка: `go test -count=1 ./...` проходит; HTML не содержит сырого JSON-предпросмотра, проверка текущего доступа возвращает понятный HTTP 409 для `pending`. Тестовая заявка была сверена по ID, пользователю, ресурсу, праву, статусу и причине; из изолированной БД удалены ровно одна заявка и по одной связанной записи аудита и outbox. После развёртывания проверяются форма и доступность тестового чата.
