# 052 — Документы, корпоративный календарь и группы мессенджера

Вопрос о содержании инструкции или анонса получает ответ по RAG. Если пользователь также запросил текущие данные сервиса, проверенные факты этого сервиса добавляются отдельно. Для вопроса только о документе итоговая модель получает найденные фрагменты без инструментов Jira.

Если планировщик одновременно отметил документацию и персональную рекомендацию, запрос обрабатывается по документации. Отдельные намерения, например вывести назначенные задачи или проверить расписание, сохраняются.

Корпоративные даты проверяются отдельным MCP-инструментом `calendar_company_events`. Он читает `MOCK_COMPANY_CALENDAR_JSON` и использует существующую проверку доступа календаря. Файл `company-calendar.json` хранит расписание демо-компании отдельно от календаря наставника. Анонсы из `fixtures/knowledge/company-events.md` объясняют формат участия и индексируются в Qdrant. При добавлении анонса в существующий стенд запускается `POST /v1/knowledge/reindex`.

Для запросов вида «в ближайшие N дней» планировщик возвращает `days_ahead`. Сервер проверяет диапазон от 1 до 31 и считает обе границы от момента запроса. Календарный `GET /health` проверяет, что все настроенные файлы читаются.

Последние сообщения конкретной группы запрашиваются с фильтром. Если первоначальный план потерял группу, модель отдельно уточняет фильтр по исходному вопросу. Неопределённый фильтр требует уточнения. Пустой результат из конкретной группы не запускает поиск по другим группам.
