# SDD-011: Аудит источников и запрет mock в runtime

## Новый контракт команды и доступов

Приложенный пользователем контракт «SDD-007: контракт сервиса команды и доступов» описывает отдельный Go-сервис с PostgreSQL, пользователями, командами, ресурсами, заявками, реальными решениями согласующих, JWT и событиями Kafka. Это проектируемый сервис, а не уже доступный источник данных. Пока сервис не реализован и не подключён, Бобби не утверждает, что знает состав команды, наставника или права пользователя, и не создаёт заявку по этому контракту. Векторный индекс документов не подменяет каталог команды и прав.

## Текущие источники

- Общие знания модели: обычные вопросы без обязательных ссылок.
- Qdrant: фрагменты Playbook и чек-листа с путём/URL источника для внутренних процессов. При ошибке поиска отсутствие фрагментов явно отмечается в промпте.
- Jira MCP: только чтение реальных задач настроенного проекта при `JIRA_MODE=live`; при `off` задачи Jira не выдаются.
- Напоминания: только реальные назначенные задачи Jira с `duedate`, без генерации демонстрационных задач.
- История: в распределённом режиме реальные запросы и ответы из PostgreSQL `ai_jobs`; текущий локальный Compose историю не сохраняет.

## Запрет подмены

Рабочий `JIRA_MODE` принимает только `off` и `live`; значение `mock` отклоняется. Создание прежней тестовой Jira-заявки не зарегистрировано в API. Заглушки HTTP и источников остаются только в автоматических тестах. Контракт команды и доступов должен реализовываться отдельным сервисом без runtime mock и с проверками авторизации, описанными в приложенном SDD.

## Граница готовности

Текущий чат не подключён к новому сервису команды и доступов: его код, миграции и запущенный контейнер отсутствуют в этом дереве. Нельзя считать эту интеграцию реализованной до сквозного сценария с двумя пользователями, заявкой, решением согласующего и проверкой выданного права.
