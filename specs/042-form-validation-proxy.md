# SDD-042: проверка встроенной формы перед отправкой

## Ошибка

Встроенная форма вызывает `POST /v1/forms/{id}/validate` после нажатия «Проверить заявку». API Бобби не регистрировал этот маршрут, поэтому gateway возвращал HTTP 405, а интерфейс показывал общее сообщение «Не удалось проверить форму». Это воспроизведено на `bobby-mocks` через тот же публичный путь. Опубликованная схема запроса оборудования требует `item` и `reason` длиной хотя бы два символа; значения на снимке удовлетворяют этим ограничениям.

## Контракт

- API принимает подписанную демо-сессию, токен команды, ID формы, её версию и значения полей из опубликованной схемы. Проверка не отправляет заявку и не создаёт ключ идемпотентности.
- API передаёт значения на существующий маршрут валидации сервиса прав. Правила полей задаёт опубликованная JSON Schema; Бобби не содержит список названий полей или конкретных допустимых значений.
- Успех сервиса прав и совпадение версии дают ответ `valid: true`. Некорректные значения дают HTTP 400, устаревшая версия — HTTP 409, недоступный сервис — HTTP 503. Отсутствие сессии даёт HTTP 401.
- После успешной проверки прежний отдельный шаг подтверждения отправляет форму с теми же значениями и ключом идемпотентности. Сообщение об успехе появляется только после подтверждённого ответа сервера.

## Проверка

Тест маршрута проверяет передачу значений и токена в сервис прав, успешный ответ, отсутствие токена, отсутствие значений и несовпадение версии. После локальных Go и frontend тестов нужно пересобрать API в `bobby-mocks`, повторить форму запроса оборудования и проверить, что «Проверить заявку» открывает шаг подтверждения без красной ошибки.

Проверка на тестовом стенде: до исправления API `POST /v1/forms/equipment-request/validate` вернул 405; после сборки API из `main` тот же запрос вернул `valid: true`, версия 1. Отправка доступа к уже запрошенному учебному ресурсу вернула 409. Интерфейс теперь показывает текст этого состояния обычным уведомлением и позволяет изменить форму после конфликта; успешный статус не выдаётся при 409.

После подтверждённого ответа сервера с номером заявки интерфейс показывает точный текст «Заявка успешно отправлена!». Повторная заявка со статусом 409 остаётся отдельным состоянием и не получает ложного подтверждения.
