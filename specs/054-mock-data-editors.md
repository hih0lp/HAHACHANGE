# SDD-054. Редакторы учебных Jira, календаря и GitLab

В локальном демо на странице «Мои задачи» наставник открывает редактор
рядом с Jira, календарём или GitLab. Стажёры видят назначенные задачи,
события календаря и доступные учебные проекты. Доступ к редактору проверяет
сервис по JWT Team Access (`approver`). Выбор роли в UI отвечает за
видимость кнопок. Доступ к демороли следует правилам демостенда.

- Jira: добавление, правка и удаление задач. Поля включают исполнителя,
  описание, статус, начало и срок. Существующие дополнительные поля
  сохраняются. Напоминания и Jira MCP читают тот же набор данных.
- Календарь наставника и календарь компании: добавление, правка и удаление
  событий. Поля включают статус, описание, начало и конец. Ввод времени
  происходит по Москве. Результат занятости выводится
  из того же набора событий, как и раньше.
- GitLab: добавление, правка и удаление демопроектов, веток, коммитов и
  merge requests. Можно настроить видимость проекта по стажёру и изменить
  статус MR или апрува. Основная ветка и ветки MR должны существовать.
  Наставник читает проекты обоих стажёров. Общее начальное демо
  `demo/bobby-playbook` сохраняет идентификаторы проекта и MR. Эмуляция
  моделирует данные GitLab для MCP и не выполняет git push.

## API и хранение

Локальный API проксирует `GET` и `PUT /v1/mock-data/{source}` к тому
мок-сервису, который читает данные через MCP. Значения `source`:
`jira`, `calendar`, `company-calendar`, `gitlab`.
Ответ `GET` и тело `PUT` содержат `version` и `data`.
Ошибка проверки даёт HTTP 400. Несовпавшая версия даёт HTTP 409 и
сохраняет изменения другого редактора. Успешное сохранение увеличивает
версию. UI предлагает загрузить актуальные данные.

Мок-сервисы используют таблицу `bobby_mock_datasets` в PostgreSQL.
Начальный набор Jira и календарей импортируется из существующих
смонтированных файлов один раз. Начальный набор GitLab берётся из
встроенного репозитория. После импорта JSON-файлы остаются исходными
данными для чистого запуска. Редактор сохраняет в PostgreSQL. Обычные
REST и MCP используют сохранённый набор без перезапуска. Публичный
`GET /v1/tasks/gitlab` вызывает GitLab MCP с JWT пользователя.
В отсутствие `MOCK_DATABASE_URL` старый режим запуска доступен для
отдельных установок, включая профиль записи файлов.

## Приёмка

В роли наставника через интерфейс добавить и изменить задачу, событие
и GitLab MR. Проверить пользовательское чтение и MCP соответствующей
роли, в том числе разделение прав и статус апрува. Повторить сохранение
со старой версией и получить конфликт. Перезапустить имитации и убедиться,
что новые значения сохранились. Для повторных тестов удалить добавленные
учебные записи.

Проверено на локальном стенде: браузерные сохранения в Jira, обоих
календарях и GitLab, смена апрува MR, удаление GitLab-проекта, чтение
через MCP, HTTP 403 у стажёра, HTTP 409 для устаревшей версии и сохранность
данных после перезапуска трёх мок-сервисов. Временные записи удалены.
