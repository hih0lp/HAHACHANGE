# SDD-060. Проверки сценариев для сдачи

Запуск на чистых томах описан в [SDD-046](046-local-compose.md).
Автоматический прогон использует отдельные PostgreSQL и Redis.
Тесты подменяют ответы LLM, поискового сервиса и корпоративных
интеграций контролируемыми данными. Браузерные проверки используют
реальные компоненты React и подставляют ответы API.

| Сценарий | Что проверяют тесты |
| --- | --- |
| Вопрос и уточнение в рабочем чате | Бобби выбирает источник по текущему вопросу. Для GitLab подтверждает данные вызовом из каталога MCP. Для документации сохраняет проверенную ссылку и показывает найденные источники, если модель не подтверждает ответ. [SDD-055](055-mcp-grounded-followups.md) |
| Задачи, календарь, GitLab и мессенджер | Неподтверждённые данные обозначаются явно. Браузер проверяет карточки Jira, календарь и редактирование моков. При конфликте версий пользователь может загрузить свежий список. [SDD-054](054-mock-data-editors.md), [SDD-057](057-item-editing-ui.md) |
| Подтверждённое действие | Стажёр проверяет значения, подтверждает учебную заявку и видит квитанцию. Повтор с тем же ключом возвращает сохранённый результат. Другой пользователь не получает доступ к чужой заявке. [SDD-042](042-form-validation-proxy.md) |
| Задание в очереди | API проверяет сессию и владельца. Повторная доставка не генерирует второй ответ. После завершения временный токен удаляется из Redis. [SDD-006](006-distributed-jobs.md) |

Команда и результаты опубликованы в [отчёте](../TEST_REPORT.md).
Для приёмки сверяются доли покрытых исполняемых строк отдельно для Go
и React. Цель команды около 90%, минимум кейса строго выше 80%.
Тесты, зависимости и сборка фронтенда в знаменатель не входят.
