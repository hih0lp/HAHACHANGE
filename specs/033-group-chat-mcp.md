# SDD-033. Поиск по истории корпоративных групп

## Сценарий

Стажёр задаёт «Бобби» вопрос об обсуждении за конкретный период. Клиент запрашивает подтверждённые реплики через MCP и составляет краткий ответ. Для демонстрации команда может добавить новую реплику через HTML-форму. Переписки синтетические.

## Запуск

```sh
docker compose -p bobby-group-chat -f compose.mock-group-chat.yml up -d --build
```

Форма доступна на [порту 18082](http://localhost:18082/) без входа. Она показывает тестовые группы и авторов и добавляет сообщения. Время в форме задаётся по Москве. Без указанного времени используется текущее. При первом запуске TEI скачивает модель. Сервис повторяет запуск, пока зависимость загружается. Готовность БД и заполнение можно проверить через `GET /health` сервиса после его запуска.

Для локального получения токена используйте существующий endpoint team-access `POST http://127.0.0.1:18083/v1/auth/login` с JSON `{"username":"intern","password":"chat-demo-intern"}`. Ответ содержит `access_token`. Для второго стажёра используйте `intern2` и `chat-demo-intern2`. Эти пароли предназначены для изолированного демо. Регистрация не требуется.

На общем стенде соберите `Dockerfile.mock-group-chat` и подключите сервис к существующим PostgreSQL, team-access и TEI. Для контейнера нужны:

Для тестового стека `bobby-mocks` готово наложение `compose.mock-group-chat.shared.yml`: оно использует уже работающие PostgreSQL, каталог команды и TEI, не создавая вторую модель. Из каталога с тестовой `.env` запустите:

```sh
docker compose -p bobby-mocks -f compose.distributed.yml -f compose.mock.yml -f compose.mock-group-chat.shared.yml up -d --build mock-group-chat
```

Форма и `/health` доступны на `http://127.0.0.1:${GROUP_CHAT_LOCAL_PORT:-28084}/` с самого сервера. MCP внутри проекта доступен по `http://mock-group-chat:8080/mcp`. Наложение использует отдельные таблицы `chat_*` в тестовой базе проекта; оно не подключает инструмент автоматически к ответам Бобби. Для теста из другой машины используйте SSH-туннель к локальному порту, так как форма допускает запись без входа.

| Переменная | Значение |
| --- | --- |
| `CHAT_DATABASE_URL` | DSN отдельной БД или схемы для переписок. У роли должны быть права на создание и изменение таблиц в этой схеме |
| `CHAT_TEAM_ACCESS_URL` | Базовый внутренний URL каталога команды, например `http://team-access:8080` |
| `CHAT_EMBEDDINGS_URL` | Базовый внутренний URL TEI с моделью `intfloat/multilingual-e5-small` |
| `CHAT_PORT` | Порт HTTP внутри контейнера. По умолчанию `8080` |

Публикуйте корневой путь сервиса для HTML-формы. В комплектном Compose порт можно изменить через `CHAT_HOST_PORT`, порт локального входа через `CHAT_LOCAL_TEAM_PORT`. Для MCP внутри той же сети Compose используйте `http://mock-group-chat:8080/mcp`.

## MCP

Транспорт Streamable HTTP на `/mcp`. Передавайте `Authorization: Bearer <JWT пользователя>` на каждом запросе, включая инициализацию, `tools/list` и `tools/call`. Сервис вызывает `GET /v1/me` каталога и использует подтверждённый ID. Ответ HTTP 401 означает отсутствующий или недействительный токен, 503 — недоступность проверки личности.

Инструмент `search_group_messages` принимает:

| Аргумент | Формат |
| --- | --- |
| `query` | Тема или идентификатор задачи, 1–300 символов |
| `from`, `to` | RFC 3339, начало включительно, конец исключительно. Допустимый интервал до 31 суток |
| `group_id` | Необязательный ID группы |
| `limit` | До 30 сообщений вместе с контекстом, по умолчанию 15 |

Пример `tools/call` после инициализации MCP:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "search_group_messages",
    "arguments": {
      "query": "обновление выдачи",
      "from": "2026-11-13T00:00:00+03:00",
      "to": "2026-11-14T00:00:00+03:00",
      "group_id": "product"
    }
  }
}
```

При ручной проверке подставьте даты за вчера относительно **первого запуска на данной БД**. Клиент переводит относительные даты в границы календарного дня пользователя. Результат инструмента содержит `structuredContent`:

```json
{
  "messages": [
    {
      "message_id": "1",
      "group_id": "product",
      "group_name": "Команда продукта",
      "author_name": "Наставник",
      "sent_at": "2026-11-13T07:00:00Z",
      "text": "По новому ранжированию каталога: предлагаю начать с 10% трафика и следить за долей пустых результатов.",
      "is_context": false
    }
  ]
}
```

При отсутствии совпадений, неизвестной или недоступной группе результат — `{"messages":[]}`. Реплики с `is_context: true` — соседние сообщения той же группы в пределах пяти минут и запрошенного диапазона. Для выжимки упорядочьте реплики по времени внутри группы, укажите группу и время источника и уточните тему, если совпадения относятся к разным обсуждениям. Текст переписки и соседние реплики передаются модели как данные для ответа согласно SDD-031. При ошибке инструмента сообщите, что поиск временно недоступен.

## Хранилище и поиск

PostgreSQL хранит группы, членство и сообщения. Ключ автора и группы в сообщении ссылается на членство. При заполнении тестовыми данными UTC-время вычисляется из даты первого запуска по Москве. Ключи тестовых сообщений уникальны, поэтому повторное заполнение сохраняет исходные даты и ручные записи.

После фильтрации по членству и периоду поиск объединяет точные совпадения, полнотекстовый поиск PostgreSQL с конфигурацией `russian` и косинусное сходство эмбеддингов. Для демо векторы нормализованы и хранятся в PostgreSQL как `real[]`. Сходство считается по доступным сообщениям в заданном окне. При смене модели переписки потребуется переиндексировать. Новая реплика сохраняется вместе с вектором одной операцией. При недоступности TEI форма возвращает ошибку и сохраняет введённое сообщение только после успешной повторной отправки.

Группа `product` общая. `catalog` доступна `intern` и `approver`, `search` доступна `intern2` и `approver`. HTML-форма специально допускает запись от любого из этих тестовых участников. История доступна через авторизованный MCP.

## Приёмка

- На чистой БД найдите вчерашнее обсуждение «обновления выдачи» в `product`, включая решение о запуске.
- Добавьте в форме реплику в `product` с уникальным номером задачи, затем найдите её по этому номеру и периоду.
- Вызов с `group_id: "search"` и запросом `SEARCH-42` за вчера возвращает совпадение для `intern2` и пустой список для `intern`. Поддельный JWT отклоняется.
- Автоматическая проверка с PostgreSQL и детерминированной заглушкой TEI: `TEST_DATABASE_URL=<test-dsn> go test -count=1 -cover ./cmd/mock-group-chat`. Используйте тестовую БД, роль создаёт и удаляет временную схему. Заглушка проверяет путь семантического совпадения, качество перефразировок на реальной модели проверяется на стенде.

Проверка: go test -count=1 -cover ./... с PostgreSQL 18 и заглушкой TEI прошёл. Покрытие операторов нового пакета — 60,6%. Docker Compose и качество ранжирования на реальной модели в этой проверке не запускались.

Проверка общего Windows-сервера 14 ноября 2026: отдельный `bobby-group-chat` потребовал отсутствующий образ PostgreSQL 16; пробный запуск с отдельным TEI столкнулся с занятыми портами и временно перегрузил Docker Desktop. Engine восстановлен, временный проект удалён без удаления volumes. Сервис в `bobby-mocks` с общими зависимостями ответил `/health` HTTP 200, поиск `SEARCH-42` за вчера вернул 0 сообщений стажёру 1 и 2 сообщения стажёру 2; запрос без токена получил HTTP 401. Основной чат при этом отвечал HTTP 200.
