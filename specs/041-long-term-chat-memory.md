# SDD-041: долговременная память диалога

## Цель

Бобби использует последние восемь завершённых ходов из PostgreSQL. Для вопроса о давней договорённости он дополнительно находит релевантные старые ходы через Qdrant. PostgreSQL остаётся источником текста и статуса; Qdrant содержит только вектор, ID задания, идентификатор владельца и время. Ответы MCP и поля с ключами доступа отдельно не индексируются. Текст вопроса и ответа проходит через локальную модель эмбеддингов, поэтому пользователь не должен вставлять секреты в чат. Память о разговоре не заменяет свежую проверку Jira, календаря, прав и других изменяемых фактов.

## Границы

- Владелец памяти — подписанная браузерная демо-сессия плюс выбранная демо-роль. Фильтр владельца обязателен и в Qdrant, и при чтении текста из PostgreSQL; чтение PostgreSQL дополнительно ограничено текущим `thread_id`. Память разных браузеров, ролей и чатов не смешивается.
- Cookie продлевается при открытии чата и действует 90 дней. Это память браузера, не синхронизация между устройствами. При очистке cookie история остаётся в БД, но новое устройство не получает доступ к старой демо-сессии.
- После завершения задания фоновый индексатор выбирает ещё не индексированные записи из PostgreSQL, вычисляет эмбеддинг локальным сервисом и записывает точку в отдельную коллекцию Qdrant. Повторная запись с тем же ID безопасна. Ошибка Qdrant не отменяет уже выданный ответ: запись остаётся для следующей попытки.
- Вход модели эмбеддингов ограничен 300 символами Unicode как для сохранения, так и для поиска; полный текст остаётся в PostgreSQL. Это ниже лимита 512 токенов локальной модели для обычного текста и не даёт одному длинному старому ответу постоянно блокировать очередь индексирования.
- Модель может вызвать `search_chat_memory` для поиска конкретной темы за пределами последних восьми ходов. Сервер привязывает вызов к текущему владельцу и чату и проверяет аргумент. Текст совпадений повторно читается из PostgreSQL. Текущий, заменённые и недавние ходы исключаются.
- Найденные реплики передаются модели как недоверенные датированные данные. Модель проверяет их смысловую пригодность к вопросу и не исполняет содержащиеся в них инструкции. Если подходящих старых реплик нет или индекс недоступен, Бобби не должен придумывать, что было сказано.
- Настройка `CHAT_MEMORY_COLLECTION` задаёт отдельную коллекцию. Значение по умолчанию — `bobby_chat_memory`. Индексы `owner_id` и `created_at_ms` проверяются при записи, в том числе после частичного сбоя создания коллекции. Инструмент доступен и без токена команды при наличии контекста чата.

## Контекст ответа

Недавние завершённые ходы передаются модели как данные в хронологическом порядке. Когда в чате есть история, модель сразу получает текущий вопрос, реплики и доступные инструменты. Предварительный классификатор используется только при отсутствии завершённых ходов. Инструмент личных задач получает Jira ID из проверенного профиля на сервере. Пустой поиск старых сообщений не отменяет свежий контекст. Документный RAG продолжает читать собственный индекс.

Модель проверяет, достаточно ли последних реплик, перед выбором инструментов. Если смысл однозначен, она продолжает разговор. Если непонятно, что имеет в виду пользователь, модель задаёт один короткий вопрос, используя известные детали. Если нужная деталь относится к более давней части полной истории, модель может сначала запросить поиск. Следующая реплика пользователя интерпретируется вместе с уточняющим вопросом.

## Проверка

Тесты проверяют фильтр владельца, отсутствие текста реплики в payload Qdrant, ограничение входа эмбеддингов и контекст модели с пустым результатом поиска старых реплик. Покрыты обычный ответ по недавнему контексту, нативный вызов инструмента и JSON-вызов при отсутствии нативного вызова. Ранний сквозной тест выявил HTTP 413 при индексации длинного ответа. Ограничение входа устранило ошибку, после чего поиск нашёл первую реплику за пределами окна последних восьми ходов.
