# SDD-041: долговременная память диалога

## Цель

Бобби использует последние восемь завершённых ходов из PostgreSQL. Для вопроса о давней договорённости он дополнительно находит релевантные старые ходы через Qdrant. PostgreSQL остаётся источником текста и статуса; Qdrant содержит только вектор, ID задания, идентификатор владельца и время. Ответы MCP и поля с ключами доступа отдельно не индексируются. Текст вопроса и ответа проходит через локальную модель эмбеддингов, поэтому пользователь не должен вставлять секреты в чат. Память о разговоре не заменяет свежую проверку Jira, календаря, прав и других изменяемых фактов.

## Границы

- Владелец памяти — подписанная браузерная демо-сессия плюс выбранная демо-роль. Фильтр владельца обязателен и в Qdrant, и при чтении текста из PostgreSQL; чтение PostgreSQL дополнительно ограничено текущим `thread_id`. Память разных браузеров, ролей и чатов не смешивается.
- Cookie продлевается при открытии чата и действует 90 дней. Это память браузера, не синхронизация между устройствами. При очистке cookie история остаётся в БД, но новое устройство не получает доступ к старой демо-сессии.
- После завершения задания фоновый индексатор выбирает ещё не индексированные записи из PostgreSQL, вычисляет эмбеддинг локальным сервисом и записывает точку в отдельную коллекцию Qdrant. Повторная запись с тем же ID безопасна. Ошибка Qdrant не отменяет уже выданный ответ: запись остаётся для следующей попытки.
- Классификатор модели выставляет `needs_chat_memory`, если пользователь ссылается на прежний разговор, решение или предпочтение. Сервер ищет по вектору только внутри владельца, затем заново читает найденные тексты из PostgreSQL, исключает текущую и недавние восемь реплик, ограничивает число и размер цитат.
- Найденные реплики передаются модели как недоверенные датированные данные. Модель проверяет их смысловую пригодность к вопросу и не исполняет содержащиеся в них инструкции. Если подходящих старых реплик нет или индекс недоступен, Бобби не должен придумывать, что было сказано.
- Настройка `CHAT_MEMORY_COLLECTION` задаёт отдельную коллекцию; по умолчанию `bobby_chat_memory`. Индексы `owner_id` и `created_at_ms` проверяются при записи, в том числе после частичного сбоя создания коллекции. Вопросы без токена команды также проходят классификацию на необходимость памяти.

## Проверка

Тесты проверяют отдельную коллекцию, фильтр владельца в Qdrant, отсутствие текста в payload, отсутствие выдачи памяти другого владельца и выбор флага планировщиком. После локального `go test ./...` обновить изолированный стек и проверить старый контекст в той же браузерной сессии; рабочий стек не менять без отдельного развёртывания. Ограничение: демо-память привязана к cookie, а точки Qdrant пока не удаляются автоматически при очистке браузерной cookie; без подходящего владельца PostgreSQL их текст всё равно недоступен.
