# SDD-029: Editable Jira and Calendar MCP simulators

Two independent Go services provide the existing Jira and Google Calendar MCP tool names to an isolated Bobby stack. The Jira simulator loads `fixtures/mock/jira.json` on each request; the calendar simulator loads `fixtures/mock/calendar.json` on each request. No response is cached, and invalid JSON returns an error. The source snapshots were read on 13 November 2026 from the live demo MCP services. They contain seven SCRUM issues and the mentor calendar's seven upcoming events. Credentials and attendee email addresses are excluded. Mock URLs in issue data identify the captured demo Jira, but the simulator never calls Jira or Google.

The Jira fixture holds `project_key` and ordered `issues`; each issue has key, summary, status, status_category, description, optional due/start dates, optional assignee account ID/name, URL, and optional display-name-to-value fields. MCP provides issue detail, recent list, assigned list and all nonempty fields. The read-only `/rest/api/3/search/jql` endpoint supports the existing reminder scan, including status category. Bobby's `JIRA_MODE=mock` accepts an internal HTTP origin without live credentials; `live` retains its HTTPS and credential validation.

The calendar fixture holds `calendar_id`, `summary`, `time_zone`, and `events` with IDs, start/end RFC3339 timestamps, titles, optional descriptions and links. Event queries return Google-like `data.items`; free/busy derives UTC busy intervals from the same events, avoiding inconsistent slots. Queries use half-open range overlap and retain the 31-day limit. The calendar MCP verifies the bearer against team-directory `/v1/me` and the configured demo subject. Both binaries bind only to `127.0.0.1:8080` when launched locally; Compose explicitly sets `MOCK_LISTEN=:8080` on its private network, without publishing the mock service ports to the host.

For an isolated test launch, use a different Compose project name and `compose.distributed.yml` plus `compose.mock.yml`, with `BOBBY_LOCAL_PORT=18001`, `BOBBY_REMOTE_BIND=127.0.0.2`, `BOBBY_REMOTE_PORT=18001`, `BOBBY_TEAM_PORT=18082`, and `BOBBY_RIGHTS_PORT=18083`. The test stack uses its own PostgreSQL/Redis/Kafka and mounts the two JSON files read-only; the production Compose project and URL remain unchanged. The fixture files are edited on the host and are reloaded at the next MCP or reminder request. Validate MCP tools/list and tools/call, mock Jira search, team bearer denial, empty and changed ranges, then ask Bobby about SCRUM-7, personal tasks, events and mentor busy time.

Verification on 13 November 2026: `go test ./...` passed during the initial build. Local Jira MCP `tools/list` exposed four tools, and `jira_get_issue(SCRUM-7)` returned the captured dates, assignee and empty description. Server images built successfully. The calendar MCP returned two events and two corresponding busy intervals for 17–20 November. A separate test-only `.env` was provided with the user's approval; the production `.env` was neither read nor copied. The `bobby-mocks` Compose project runs on the server with its own database, queue, cache, keys and image tags. The mock MCP containers have no published host ports. The production containers continue to run with their original configuration.

The test chat at server localhost port 18001 issued an intern team session and completed questions about SCRUM-7, the intern's assigned tasks, and the 17–20 November events. It reported SCRUM-7 as in progress, assigned to Gapshin Mihail, starting 10 November, due 13 November, with an empty description. The assigned-task answer returned SCRUM-7. The event answer returned 17 November 15:30–16:00 MSK and 19 November 16:00–17:00 MSK. The captured SCRUM-7 summary itself is a nonsense string beginning with a backslash; it is preserved literally in `jira.json`, not reconstructed from PowerShell's garbled terminal output. The team directory accepts the internal HTTP Jira origin only when `JIRA_MODE=mock`; the production HTTPS validation remains in force.

The initial test-chat answer about 19 November availability also claimed 13:00–14:00 MSK, an interval absent from the fixture and MCP result. Bobby now formats direct calendar questions from MCP data in the mock stack: events from `items` and occupied time from `busy`. This keeps the answer tied to the editable JSON and prevents the model from adding a slot. The formatter tests check that UTC 13:00–14:00 becomes 16:00–17:00 MSK and reject missing data. The production answer path remains unchanged.
