# SDD-018: GitLab MCP, рекомендации и план слияния

Ветка codex/gitlab-calendar-recommendations, основание 735989b. Согласованный полный объём описан в SDD-016.

## Реализовано в этой ветке

- Отдельный Go-сервис GitLab MCP по маршруту /mcp. Инструменты чтения: дерево, файл по ref, история и diff коммитов, список и diff MR, состояние approvals и pipeline. GitLab API вызывается с фиксированного origin и с ограниченным по размеру ответом.
- Демонстрационная привязка: сервис проверяет bearer пользователя через каталог команд и сравнивает полученный ID с GITLAB_DEMO_SUBJECT. Для доступа к GitLab используется отдельный read-only токен из Docker secret. Этот режим предназначен для изолированного демо с тестовыми данными. Общая сессия Бобби не подходит для личных токенов. Персональный OAuth остаётся следующим этапом.
- Worker узнаёт инструменты через tools/list и отправляет вызовы через tools/call. Настройка GITLAB_MCP_URL по умолчанию пустая. Недоступный каталог GitLab не блокирует другие источники. Worker использует пользовательский bearer для GitLab MCP, ключ API Бобби туда не отправляется.
- Добавлены инструкции модели для рекомендаций и оценки навыков с опорой на документацию Авито, роль, практику команды, релевантные задачи и другие доступные источники. Навыки сотрудников и критерии оценки пока не заведены отдельным каталогом.

## Docker

compose.gitlab-demo.yml описывает отдельный проект bobby-gitlab-demo с именованными томами и портом 127.0.0.1:18929. Для браузера имя gitlab.local должно разрешаться в loopback. В стабильном окружении задаётся конкретный GITLAB_IMAGE. GitLab на Docker Desktop Windows используется для пробного запуска.

compose.gitlab-integration.yml — дополнение к compose.distributed.yml для изолированного тестового стека. Перед применением базового Compose задать отдельные порты, имена образов и тома или использовать отдельный Docker Engine. GITLAB_API_ORIGIN должен быть доступен из контейнера адаптера. Указать GITLAB_DEMO_SUBJECT и GITLAB_DEMO_TOKEN_PATH, файл токена хранить вне Git. Для сквозной проверки нужны тестовый проект и реальный read-only токен.

## Календарь и следующие шаги

С 10 ноября по 9 декабря 2026, МСК, будни 09:00–18:00. «Онбординг стажёра»: знакомство и обзор доступов, регулярный 1:1, цели и трекер прогресса, документы команды, Go и базы данных, итоговая сверка. «Доступность ментора»: окна вопросов, разбора ревью и 1:1. Время и события учебные. Источник содержания — локальная выдержка открытого чек-листа Авито.

Остаются отдельные календари и календарный MCP, личный OAuth GitLab, демо MR с состояниями ревью, канал напоминаний и сквозная проверка с реальным GitLab. Рекомендации ещё нужно проверить на тестовом профиле стажёра и разных наборах доступных источников.

## Слияние

Сверить изменения второго worktree в cmd/server/answer.go и cmd/server/distributed_runtime.go. При конфликте сохранить маршрутизацию форм и прав, добавить опциональную маршрутизацию GitLab с её bearer без внутреннего API-ключа. Dockerfile и два новых Compose-файла независимы от базового Compose. Миграции общей БД отсутствуют. После слияния выполнить go test ./... и проверить обычный чат, формы прав, GitLab tools/list и tools/call, а также отказ при другом ID пользователя.
