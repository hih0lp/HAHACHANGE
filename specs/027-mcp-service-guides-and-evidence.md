# SDD-027. Выбор MCP и подтверждение источника

Рабочие инструкции для GitLab, Jira, календаря, командного профиля и сервиса доступов находятся в `cmd/server/mcp-guide.md`. Worker добавляет их в системный контекст. Схемы инструментов получает из `tools/list` и передаёт как OpenAI function tools. Модель выбирает источник по смыслу, а сервер вызывает `tools/call` с разрешённой учётной записью и передаёт структурированный результат. Названия инструментов и схемы не являются пользовательскими фразами для маршрутизации.

Планировщик указывает необходимые источники. Ошибка получения каталога журналируется. Для определённых планировщиком источников ответ требует успешного вызова в текущем запросе. При отсутствии доказательств сервер сообщает об ограничении, даёт адрес для ручной проверки и отдельно помечает ссылки на документы. Признак успеха источника не проверяет истинность каждого утверждения модели и не доказывает полноту выборки.

Руководства различают типы данных: GitLab даёт проекты, содержимое репозитория, историю, MR и CI. Jira связывает персональный список с проверенным account ID. Календарь разделяет опубликованные события и интервалы занятости. Командный MCP подтверждает профиль и состав. MCP доступов проверяет права и предлагает формы, а подачу запускает обработчик подтверждения.

GitLab MCP использует штатный Compose-сервис `gitlab-integration`. Его поддерживаемая привязка ограничена настроенным демо-пользователем. Проверка `python scripts/check-gitlab-mcp.py` авторизуется как демо-стажёр, проверяет 14 инструментов и выполняет чтение проектов через адрес, настроенный у worker. Пустой список допустим для аккаунта без проектов. Сбой авторизации или интеграции завершает проверку с ошибкой.

Планировщик получает каталог MCP текущей сессии с описаниями и схемами. Для обзора содержимого модель может выбрать инструмент списка проектов; worker проверяет его наличие в каталоге GitLab, вызывает с текущей командной сессией и выводит полученные проекты. Выбор не зависит от шаблонов фраз.
