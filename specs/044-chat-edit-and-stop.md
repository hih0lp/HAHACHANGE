# SDD 044 — Редактирование вопроса и остановка ответа

## Поведение

Действие редактирования доступно, пока вопрос в очереди или обрабатывается. Пользователь меняет текст и отправляет его заново. Сервер создаёт новое задание с тем же сценарием, а старое помечает `superseded_at`; история и поиск по памяти не включают заменённый вопрос и ответ. Новое задание проходит обычную очередь и поступает в Qwen. Если текст не изменён, новый запрос не создаётся.

Для задания в очереди или в обработке доступно действие «Остановить ответ». API переводит его в терминальный статус `failed` с причиной `Остановлено пользователем`. Воркер раз в 300 мс сверяет статус и токен аренды задания с PostgreSQL. При остановке он отменяет контекст запроса; запрос к Qwen создан через `http.NewRequestWithContext`, поэтому соединение прерывается. Условная запись результата по токену аренды не позволяет позднему ответу вернуть остановленное задание в `completed`. Уже завершённое задание остаётся без изменений.

## API и данные

Карандаш исчезает после завершения, ошибки или остановки ответа. Если редактирование было открыто, поле ввода возвращается к прежнему черновику. Сервер атомарно заменяет исходное задание личного чата. Ограничение действия статусами очереди и обработки применяется в интерфейсе.

Карандаш загружает текст вопроса в обычное поле ввода под перепиской. Enter или стрелка отправляют изменённый вопрос. Крестик и Escape отменяют правку. После отмены или отправки возвращается прежний черновик с цитатами. В основном и мини-чате квадрат «Остановить ответ» доступен, пока последний активный запрос в очереди или в обработке. В обычном режиме квадрат занимает место стрелки. Введённый за это время черновик сохраняется после остановки.

- `POST /v1/jobs/{id}/edit` с JSON `{ "query": "..." }` возвращает `202` и новое задание, `Location` указывает на него.
- `POST /v1/jobs/{id}/stop` с пустым JSON возвращает `200` и текущее состояние задания.
- Оба маршрута требуют API-ключ и действуют только на задания владельца текущей браузерной сессии и демо-роли. Редактирование поддерживается для исходного личного чата, но не для групповой ветки.
- Поле `ai_jobs.superseded_at` добавлено в основную миграцию и создаётся при запуске для существующей базы. Старые строки остаются для аудита; в истории и контексте LLM их нет.
- В Redis передаётся командный токен только нового задания. Старый токен удаляется.

## Проверка

Проверить отправку обоих POST с правильным владельцем, появление нового вопроса в истории и отсутствие старого, остановку задания до получения ответа, невозможность повторной записи результата, независимость других заданий. Для интерфейса проверить карандаш, сохранение, отмену изменения, кнопку остановки и нейтральную надпись после остановки. Команда сборки: `cd frontend && npm run build && npm test`; сервер: `go test ./internal/distributed ./cmd/server`.

Проверено: локальные Go-тесты прошли; Docker-сборка из `main` выполнила `go test -cover ./...` без ошибок, покрытие `cmd/server` составило 51,0%. Сборка frontend и семь тестов прошли. Через публичный тестовый gateway задание было остановлено в статусе `running`; сразу и через две секунды API вернул `failed`. Редактирование создало новое задание `queued`, исходное исчезло из `/v1/chat/history`, новое присутствует. Статический frontend из `main` отдаётся по тестовому URL с HTTP 200.

Нажатие на карандаш открывает редактор и сразу вызывает маршрут остановки активного задания. Кнопка отправки становится доступна после ответа сервера. Редактор остаётся открытым после остановки и позволяет отправить изменённый вопрос. Escape закрывает редактор, сохраняя исходный черновик и остановленное задание.

Проверено в Chromium отдельно: остановка по карандашу, выход через Escape с сохранением черновика, отправка изменённого вопроса и обычная кнопка остановки. Сборка и шесть тестов frontend прошли.
