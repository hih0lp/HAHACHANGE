# SDD-004: Jira MCP для AI-buddy

**Статус:** реализовано и проверено на тестовом проекте SCRUM

## Цель

AI-buddy отвечает на вопросы о состоянии и содержании тестовых задач Jira, используя свежие данные. Модель не получает API-токен Jira. Она получает только результат инструментов MCP, который сервер вызывает от имени учебного приложения.

## Архитектура и контракт

1. Go API публикует MCP Streamable HTTP на `POST /mcp` с официальным Go SDK. Сессия stateless, ответы JSON.
2. Инструмент `jira_get_issue(key)` читает summary, description, status и URL одной задачи только из настроенного проекта.
3. Инструмент `jira_list_issues()` читает до 10 недавно обновлённых задач проекта через Jira Cloud REST `/search/jql`.
4. При вопросе с ключом задачи агент вызывает `jira_get_issue`, при общем вопросе о Jira или задачах — `jira_list_issues`. Результат добавляется в контекст локальной модели наряду с RAG-фрагментами.
5. Ответ включает ссылку на задачу как источник. Интерфейс показывает кликабельную ссылку Jira.
6. MCP-инструменты доступны только для чтения. Создание задачи остаётся в `POST /v1/access-requests` после подтверждения человеком в UI.

`/mcp` использует тот же `API_KEY`, что и остальные защищённые API-маршруты. Учётные данные Jira читаются из локального `.env` контейнером и не включаются в MCP-ответ.

## Ограничения

- Это учебный проект Jira, не корпоративная Jira Авито.
- При выключенной Jira MCP-инструменты отвечают ошибкой; агент не обращается к ним. Режима mock в рабочем сервисе нет.
- Поиск Jira ограничен текущим проектом и десятью задачами. Это не универсальный Jira-поисковик.
- Роль стажёра в прототипе имитируется и не заменяет корпоративную авторизацию.

## Проверка

- Unit/integration тест поднимает MCP и тестовую Jira, проверяет чтение статуса, описания и списка задач.
- Живой MCP `jira_get_issue(SCRUM-5)` возвращает статус и URL.
- Запрос к AI-buddy «Какой статус SCRUM-5?» использует MCP и отвечает по-русски.
