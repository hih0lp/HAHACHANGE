# SDD-001: Knowledge retrieval for the Avito hackathon agent

**Status:** implemented

**Owners:** Hack&Change team

## Problem

Ответы ИИ-помощника о внутренних процессах, доступах и регламентах должны опираться на документы, а не на предположения модели. Агенту нужен единый локальный интерфейс, который находит релевантные фрагменты и сохраняет ссылку на источник.

## Goals

1. Индексировать все Markdown-документы `playbook/` в векторной БД.
2. Находить релевантные русские и английские фрагменты по смыслу.
3. Дать Go-агенту стабильный HTTP- и Go-контракт для поиска.
4. Поднимать решение одинаково через Docker Compose на сервере команды.
5. Не отправлять документы во внешние LLM/API при индексации и поиске.

## Non-goals

- Генерация итогового ответа пользователю: это ответственность агента и подключённой LLM.
- Управление доступами, выдача прав или выполнение регламентов.
- OCR, PDF/DOCX и веб-краулинг в первой версии.
- Многоарендная изоляция нескольких команд.

## Users and scenarios

### S1 — вопрос агенту

**Given** Playbook проиндексирован, **when** пользователь спрашивает «Как проходит ревью технического дизайна?», **then** агент получает до пяти фрагментов с текстом и именем исходного файла, добавляет их в контекст LLM и указывает источник в ответе.

### S2 — обновление знаний

**Given** в `playbook/` появились изменения, **when** оператор вызывает `POST /v1/knowledge/reindex`, **then** старые векторы удаляются, а индекс создаётся из текущих Markdown-файлов.

### S3 — холодный запуск

**Given** Docker Engine без volumes, **when** выполняется `docker compose up -d`, **then** локальная embedding-модель скачивается один раз, документы автоматически индексируются, и `/health` сообщает статус `ok`.

### S4 — недоступная зависимость

**Given** Qdrant или embedding-сервис ещё не готов, **when** API запускается, **then** он ждёт зависимость до 5 минут и не отвечает как готовый до успешной проверки.

## Functional requirements

| ID | Requirement |
| --- | --- |
| FR-1 | Сервис читает все `*.md`, кроме `.git/`, из `DOCUMENTS_PATH`. |
| FR-2 | Каждый документ разбивается на фрагменты с overlap; payload содержит `path`, `title`, `chunk_index`, `text`. |
| FR-3 | Для документов и запросов используется один локальный многоязычный embedding-модельный сервис. |
| FR-4 | `POST /v1/knowledge/search` принимает `query` и `limit` 1–20, возвращает отсортированные Qdrant результаты. |
| FR-5 | `POST /v1/knowledge/reindex` полностью заменяет индекс. |
| FR-6 | При заданном `API_KEY` все эндпоинты, кроме `/health`, требуют `X-API-Key`. |
| FR-7 | Пакет `pkg/knowledge` предоставляет `Search` и `BuildContext` для Go-агента. |

## Non-functional requirements

| ID | Requirement |
| --- | --- |
| NFR-1 | Сервис запускается командой Docker Compose без локального Go/Python runtime. |
| NFR-2 | API и Qdrant по умолчанию привязаны к loopback-интерфейсу. |
| NFR-3 | Данные Qdrant и модель переживают перезапуск контейнеров. |
| NFR-4 | Dockerfile отклоняет сборку при общем Go test coverage ниже 90%. |
| NFR-5 | Ошибки зависимостей не должны приводить к ложной готовности API. |

## Architecture decisions

| Decision | Rationale |
| --- | --- |
| Go + standard library HTTP | Соответствует требованию хакатона и уменьшает число зависимостей. |
| Qdrant | Поддерживает Cosine-поиск и хранит metadata вместе с векторами. |
| `intfloat/multilingual-e5-small` via TEI | Компактная локальная многоязычная модель, подходящая для русского Playbook. |
| E5 prefixes `passage:` / `query:` | Соответствует контракту модели и улучшает retrieval. |
| Отдельный `pkg/knowledge` | Агент зависит от короткого контракта, а не от деталей Qdrant/эмбеддингов. |

## Acceptance criteria

- [x] `docker compose config --quiet` завершается успешно.
- [x] `docker compose up -d` создаёт `api`, `embeddings`, `qdrant`.
- [x] `GET /health` на сервере возвращает `200` и 604 проиндексированных фрагмента.
- [x] Поиск «ревью технического дизайна» возвращает `tech_design_review.md` первым результатом.
- [x] `go test -coverpkg=./...` даёт покрытие не ниже 90% (текущий результат: 92.6%).
- [x] Пакет агента формирует контекст, содержащий путь источника и текст фрагмента.
- [x] Документы не передаются во внешний LLM/API: embedding выполняется локальным контейнером.

## Rollout and rollback

1. Запустить Compose на сервере.
2. Дождаться `/health`, выполнить тестовый запрос.
3. Подключить `pkg/knowledge` к агенту за feature flag `RAG_ENABLED`.
4. При проблеме отключить feature flag; агент продолжит работать без RAG.
5. Для остановки инфраструктуры: `docker compose down`. Volumes сохраняются.
