# SDD-008: История чата в PostgreSQL

## Основа архитектуры

SDD-006 уже определяет PostgreSQL как источник истины для запросов AI-buddy. Таблица `ai_jobs` хранит `owner_id`, вопрос, статус, ответ, ошибку и время создания. Redis ускоряет чтение статуса, Kafka доставляет задания воркерам. История чата читает PostgreSQL и не дублирует эти данные в Redis.

## Реализованный первый шаг

- `GET /v1/chat/history` доступен в распределённом режиме и возвращает до 100 последних записей `ai_jobs` для владельца текущей подписанной демо-сессии. Записи других владельцев не читаются.
- Веб-чат при загрузке восстанавливает пары «вопрос — ответ». Для заданий `queued/running` снова подписывается на WebSocket задания.
- В локальном режиме без PostgreSQL история между перезапусками не предоставляется.

## Отдельные беседы

- В распределённом режиме оба интерфейса веб-чата показывают кнопку «Новый чат» и список бесед текущей демо-сессии и роли. При открытии приложения выбирается беседа с последним отправленным вопросом.
- Кнопка открывает пустой чат. После отправки первого вопроса сервер создаёт запись в `ai_chat_threads` в одной транзакции с заданием и исходящим событием. Заголовок берётся из первых 80 символов вопроса.
- `GET /v1/chat/threads` возвращает список бесед, `GET /v1/chat/history?thread_id=…` возвращает до 100 последних пар выбранной беседы. Чужая беседа недоступна для чтения и записи.
- `POST /v1/jobs` принимает `thread_id`: `new` создаёт беседу, UUID продолжает её. Отсутствующий идентификатор или `legacy` продолжает прежнюю переписку. Старые записи с пустым `thread_id` отображаются как «Прежняя переписка».
- При переключении незавершённые задания продолжают выполняться. При повторном открытии их статус восстанавливается. Бобби получает контекст предыдущих завершённых реплик только из выбранной беседы.
- Схема бесед устанавливается при запуске API и воркера, включая существующие базы. В локальном режиме список бесед недоступен.

## Дальнейшее развитие

1. Ввести устойчивую корпоративную идентичность вместо временной cookie демо-сессии.
2. Добавить хранение системных сообщений и напоминаний, если они понадобятся в истории.
3. Сделать курсорную пагинацию вместо жёсткого лимита 100, а также политику хранения и удаления данных.
4. Зафиксировать уведомления о дедлайне в PostgreSQL с уникальностью по `(owner_id, issue_key, due_date, reminder_offset)`, чтобы они не повторялись после перезапуска.

## Ограничения

Текущий первый шаг хранит только вопросы и ответы, поскольку они уже есть в `ai_jobs`. Напоминания пока показываются только в открытой вкладке и не входят в историю. Cookie демо-сессии живёт 24 часа; после смены браузера история прежней сессии недоступна.
