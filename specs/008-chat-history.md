# SDD-008: История чата в PostgreSQL

## Основа архитектуры

SDD-006 уже определяет PostgreSQL как источник истины для запросов AI-buddy. Таблица `ai_jobs` хранит `owner_id`, вопрос, статус, ответ, ошибку и время создания. Redis ускоряет чтение статуса, Kafka доставляет задания воркерам. История чата читает PostgreSQL и не дублирует эти данные в Redis.

## Реализованный первый шаг

- `GET /v1/chat/history` доступен в распределённом режиме и возвращает до 100 последних записей `ai_jobs` для владельца текущей подписанной демо-сессии. Записи других владельцев не читаются.
- Веб-чат при загрузке восстанавливает пары «вопрос — ответ». Для заданий `queued/running` снова подписывается на WebSocket задания.
- В локальном режиме без PostgreSQL история между перезапусками не предоставляется.

## Один чат

- Оба веб-интерфейса открывают прежнюю переписку текущей демо-сессии и роли. Новые вопросы добавляются в неё.
- История и контекст Бобби включают записи с пустым `thread_id`. Сообщения ранее созданных отдельных бесед остаются в базе и не отображаются в чате.
- Маршрут списка бесед удалён. Сервер отклоняет попытки создать отдельную беседу или продолжить её через `POST /v1/jobs`.
- Шлюз тестового стека `bobby-mocks` отдаёт собранный React-интерфейс и проксирует API, WebSocket и создание демо-сессии в Go.

## Состояния Бобби в React-чате

- Новый ответ в основном чате проявляется по блокам. Если чат следит за последним сообщением, начало длинного ответа остаётся в видимой области. Восстановленная история отображается сразу. При включённом уменьшении движения текст появляется без анимации.

- При вводе Бобби слушает в аватаре рядом с последним ответом. До первой отправки слушающий Бобби появляется в приветствии.
- При отправке вопроса и обработке задания Бобби улыбается, смотрит вверх, а рядом появляются три точки. В сообщении этот аватар выровнен по строке ожидания под именем. У готового непустого ответа аватар показывает позу «отвечает».
- Спрайты используют общий масштаб. В позе «думает» персонаж расположен ниже, а точки находятся над ним. При смене состояния аватар плавно меняет положение, наклон, направление взгляда и выражение лица. Символы реакции плавно появляются и исчезают. При системной настройке уменьшения движения переход мгновенный.
- В заголовке доступной для заполнения или подтверждения формы Бобби ждёт с голубым вопросительным знаком. После получения квитанции этот спрайт скрывается.
- React-чат получает статусы задания по WebSocket и переподключается при обрыве до истечения общего срока ожидания. HTTP используется для отправки вопроса и загрузки истории.
- Только последнее сообщение может показать позу «отвечает» или «думает». Аватар без фонового круга закреплён рядом с содержимым сообщения под именем. Блоки нового ответа последовательно раскрываются слева направо. При восстановлении истории и при системной настройке уменьшения движения текст показывается сразу.

## Ответы и цитаты

- Под непустыми ответами Бобби есть иконки «Ответить» и «Копировать» с подсказками. Первая добавляет ответ целиком к черновику. Вторая копирует видимый текст ответа в буфер обмена и показывает галочку после успеха.
- При выделении текста внутри одного ответа рядом появляются «Цитировать» и «Копировать» с иконками и подписями. Эти действия используют выделенный фрагмент.
- Полные ответы и цитаты можно добавлять по нескольку штук. Они отображаются внутри рамки черновика над полем ввода, в виде серых блоков с вертикальной полосой. Крестик убирает отдельный блок. Блоки и текст вопроса общие для основного чата и мини-чата.
- При отправке чат добавляет блоки к тексту вопроса в порядке выбора. Сервер получает их в поле `query`, поэтому они сохраняются в истории вместе с вопросом. Если отправка завершилась ошибкой, блоки остаются в черновике.

## Дальнейшее развитие

1. Ввести устойчивую корпоративную идентичность вместо временной cookie демо-сессии.
2. Добавить хранение системных сообщений и напоминаний, если они понадобятся в истории.
3. Сделать курсорную пагинацию вместо жёсткого лимита 100, а также политику хранения и удаления данных.
4. Зафиксировать уведомления о дедлайне в PostgreSQL с уникальностью по `(owner_id, issue_key, due_date, reminder_offset)`, чтобы они не повторялись после перезапуска.

## Ограничения

Текущий первый шаг хранит только вопросы и ответы, поскольку они уже есть в `ai_jobs`. Напоминания пока показываются только в открытой вкладке и не входят в историю. Cookie демо-сессии живёт 24 часа; после смены браузера история прежней сессии недоступна.
