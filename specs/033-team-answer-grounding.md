# SDD-033: ответы о составе команды в тестовом чате

Повторный прогон восьми вопросов в `bobby-mocks` 14 ноября 2026 года завершился успешно для карточки Jira, личного списка, событий и занятости календаря, ссылок на обе формы и отключённого GitLab. Ответ о команде содержал служебные `ID`, `role=approver` и имя тестового пользователя вместо ясного представления проверенных связей. Источник `team_members` уже возвращает `display_name`, `is_mentor` и `is_lead` для каждого участника; отвечающая модель не должна переинтерпретировать эти поля в простом вопросе о составе или наставнике.

Если планировщик выбрал только `needs_team_directory`, Бобби получает `team_members` через MCP и формирует ответ из имён участников, а наставника и руководителя отмечает только по соответствующим булевым полям сервиса. Идентификаторы пользователей, внутренние значения `role` и Jira accountId в такой ответ не входят. Код не содержит фиксированных имён, ID или текстовых шаблонов вопроса для выбора участника; решение обратиться к сервису остаётся у LLM-планировщика. При некорректной структуре MCP Бобби явно сообщает, что состав не удалось прочитать. Составные вопросы сохраняют проверенные данные для остальных источников.

Текущий снимок Jira содержит задачи только одного реального исполнителя. В тестовой базе его `accountId` сопоставлен с `intern`; `intern2` и `approver` имеют демонстрационные ID без задач в снимке. Календарный мок настроен на субъект `intern`. Эти связи задаются тестовой конфигурацией и не должны подменяться выдуманными Jira ID или задачами для других ролей.

Проверка: тест форматирования состава и отсутствующих полей, локальный `go test ./...`, затем повторные вопросы о наставнике и команде в отдельном чате. Рабочий стек не изменяется.
