# 045 — Запись данных моков и дедлайны двух стажёров

У обоих сервисов предусмотрен `PUT /v1/fixture`. Тело — полный JSON того же формата, что и файл. Jira: `project_key` и массив `issues`; календарь: `calendar_id`, `time_zone`, необязательный `summary` и массив `events`. Это полная замена, не добавление записи: отправляйте все задачи или события, которые должны остаться. Пустой массив допустим.

Те же операции доступны через `/mcp/admin`: `jira_save_fixture` и `calendar_save_fixture`, аргумент `json` — строка с полным документом. Оба интерфейса проверяют отдельный `Authorization: Bearer …` (`MOCK_FIXTURE_WRITE_TOKEN`). Без настройки токена маршруты не регистрируются. Административные инструменты не подключаются к Бобби. Предел документа — 2 МиБ; невалидный документ оставляет старый файл, успешный PUT возвращает 204. Запись через временный файл и rename не показывает читателям частично записанный JSON. При одновременной полной замене остаётся последняя завершённая запись.

Для включения записи добавьте `-f compose.fixture-writes.yml` последним в команду Compose. Укажите `MOCK_JIRA_DATA_DIR` и `MOCK_CALENDAR_DATA_DIR`: разные каталоги вне репозитория. Перед запуском скопируйте **актуальные** `jira.json` и `calendar.json` по одному в каждый каталог. UID 10001 должен читать исходный файл и создавать и переименовывать файлы в каталоге. Примонтированного отдельно файла для атомарной замены недостаточно. Храните токен в конфигурации стенда; порты моков наружу не публикуются.

Бобби получает обновлённые данные при следующем обращении к прежнему `/mcp`: перечитываются задача, списки, события и занятость. Это существующий путь подстановки найденных данных в ответ; Qdrant остаётся для документов и памяти, моковые данные не дублируются в векторный индекс.

Минутный сканер Jira теперь обрабатывает оба профиля отдельно. Для второго стажёра используется его собственный Jira account ID из профиля команды, без подстановки ID первого. Прежние напоминания наставнику сохраняются. Дедупликация остаётся по получателю, типу, задаче и дедлайну.

Проверка на сервере: в действующих контейнерах подтверждены структуры JSON (8 задач, 7 событий). `go test ./...` прошёл. Тесты записи проверяют отказ без токена, сохранность предыдущего файла при невалидном PUT, успешный PUT, а также `tools/list` и `tools/call` через административный MCP. Доставка уведомления второму стажёру в браузере в этот прогон не входила.
