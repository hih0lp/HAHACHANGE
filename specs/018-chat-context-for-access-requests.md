# SDD-018: контекст диалога для заявок

## Наблюдение

В чате пользователь попросил доступ к возможным ресурсам, Бобби предложил выбрать ресурс, а на ответ «Давай тестовый ресурс заявки» лишь описал ресурс. Worker передавал модели одну текущую реплику без истории; выбор не был связан с предложением оформить заявку.

## Контракт

Worker при обработке задания знает ID владельца браузерной сессии и ID текущего задания. Он читает из `ai_jobs` только завершённые сообщения того же владельца, созданные до текущего задания. До восьми последних пар `user/assistant` в хронологическом порядке передаются модели перед текущим вопросом. Длина каждой реплики ограничена. JWT остаётся в Redis и не включается в историю или промпт. История другого владельца не видна.

Модель использует предыдущие реплики, чтобы понимать короткий выбор и согласие, но по-прежнему сама выбирает MCP-инструменты. Правила выбора по ключевым словам и привязки конкретного ресурса или формы в worker нет. Если в истории Бобби предложил выбрать ресурс для заявки, а пользователь выбрал его, следующая реплика должна вести к актуальной форме сервиса прав прямо в чате. Отправка сохраняет отдельное подтверждение пользователя из SDD-017.

## Проверка

Проверить выбор истории по владельцу и времени, порядок реплик, отсутствие текущего и чужого задания. В живом диалоге проверить последовательность «хочу запросить доступ» → предложение выбрать ресурс → «давай тестовый ресурс» → предложение формы. Затем проверить открытие формы в чате и отсутствие автоматической отправки.
