# SDD-037: отправка формы доступа по HTTP тестового стенда

Тестовый Бобби доступен по `http://100.105.236.12:18001/`. В этом контексте браузер не предоставляет `crypto.randomUUID()`: при проверке полей встроенной формы доступа возникает ошибка `Проверьте значения полей: crypto.randomUUID is not a function`, и запрос подтверждения не отправляется.

Обе пользовательские формы, которые создают ключ идемпотентности в браузере — встроенная форма в чате и форма сценария первой задачи — генерируют его через `crypto.getRandomValues()` из 16 случайных байт. Ключ создаётся один раз на попытку подтверждения и сохраняется при повторном запросе после сетевой ошибки. Никакие значения полей, имена пользователей или ID заявок в генераторе не зашиты. Если криптографический генератор недоступен, интерфейс показывает ошибку и не отправляет заявку без ключа.

После успешного ответа `POST /v1/forms/{id}/submit` встроенная форма в чате показывает точный текст `Заявка успешно отправлена!`. Сообщение об успехе не появляется при ошибке HTTP или проверки полей. Сервер по-прежнему возвращает ID и статус заявки в JSON для других клиентов; сам факт отправки не выдаёт право доступа. Ошибка в отдельном сценарии первой задачи исправляется тем же способом генерации ключа, его собственное сообщение о статусе сценария остаётся прежним.

Проверка в браузере после первого исправления выявила второй сбой: тестовый сервис прав не имел ни одного доступного ресурса. Кроме того, форма показывала `resource_id` и `capability` как свободный текст, хотя сервис ожидает точные ID из каталога. Тестовые ресурсы теперь задаются в редактируемом `fixtures/mock/resources.json`, загружаются сервисом прав при старте и не зашиваются в Go. Файл содержит массив `resources`; каждая запись задаёт `id`, `team_id`, `kind`, `name`, `external_ref`, HTTPS `url`, непустой массив `capabilities` и `approver_id`. Некорректный JSON, пустые обязательные поля и повторные ID останавливают сервис с явной ошибкой. Правки применяются после перезапуска `access-rights`; существующие записи с тем же ID обновляются. Удаление записи из JSON не удаляет уже использованный ресурс из БД.

Авторизованный маршрут Бобби получает профиль пользователя и список ресурсов его текущей команды из сервиса прав. Если схема формы содержит пару полей `resource_id` и `capability`, интерфейс показывает выбор из полученного каталога; доступные права меняются при выборе ресурса. Пустой каталог даёт явную ошибку. Остальные поля и формы продолжают строиться по опубликованной JSON Schema.

Проверка: тест HTML обеих страниц, работа ключа в HTTP-контексте без `randomUUID`, выбор ресурса и права из тестового каталога, подтверждение встроенной формы и сохранение прежних проверок схемы, версии, авторизации и идемпотентности. Обновляется только отдельный тестовый стенд и ветка.
