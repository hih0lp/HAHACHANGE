# SDD-008: сохраняемый сценарий первой задачи

Бадди создаёт принадлежащий пользователю экземпляр цели «первая задача → PR». Профиль, команда, ресурсы и результаты проверки прав берутся из HTTP-сервиса SDD-007. Недоступность сервиса не заменяется тестовым ответом. Bearer JWT передаётся сервису для проверки через `/v1/me`, не сохраняется в PostgreSQL и не передаётся модели.

JSON версии `1` содержит ID сценария, ревизию, цель, состояние, факты о ресурсах, сообщение и типизированный виджет. Виджет содержит `visible`, `type`, данные и действие. Фронт не исполняет произвольный HTML или URL из ответа модели.

API: `POST /v1/scenarios` создаёт сценарий; `GET /v1/scenarios/{id}` возвращает сохранённый снимок владельцу; `POST /v1/scenarios/{id}/advance` перепроверяет ближайший шаг; `POST /v1/scenarios/{id}/access-requests` отправляет подтверждённую заявку через SDD-007. Запрос действия содержит ревизию и Idempotency-Key. После неоднозначного сбоя повторяется тот же ключ. Состояние обновляется оптимистически по ревизии; устаревший клиент получает 409.

Сначала проверяются Jira-ресурсы команды; право browse_issues открывает возможность получить задачу. Затем набор предпосылок уточняется по задаче. Каталог команды не означает, что все перечисленные ресурсы обязательны. Отсутствие ресурса/команды требует уточнения, unknown означает сбой проверки, pending — ожидание заявки. Одобрение требует повторной проверки права. До проверки задачи и PR сценарий не становится completed.

Сценарий и отдельный запрос LLM — разные сущности. Сценарий сохраняется в PostgreSQL между сообщениями и перезапусками. При потере Redis долговечное состояние сохраняется. На первом этапе перепроверка выполняется явным advance; события Kafka добавят автоматическое обновление после интеграции сервиса SDD-007.
