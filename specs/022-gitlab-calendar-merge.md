# SDD-022: GitLab MCP, Calendar и слияние с чатовой веткой

Ветка codex/gitlab-calendar-recommendations основана на 735989b и объединена с локальной веткой codex/chat-access-form-20261111 на коммите 21459c7. Согласованный объём GitLab и Calendar описан в SDD-016; изменения второй ветки — в SDD-018–021.

## Реализовано в этой ветке

- Отдельный Go-сервис GitLab MCP по маршруту /mcp. Инструменты чтения: доступные проекты, ветки, теги, дерево, файл по ref, история и diff коммитов, список, карточка, комментарии и diff MR, состояние approvals и pipeline. Отдельный инструмент `gitlab_review_reminders` показывает открытые MR без черновиков и стабильный ID состояния для дедупликации. Если GitLab не сообщил об обязательных approvals, инструмент не утверждает, что одобрение обязательно. При 404 на `/approval_state` используется доступный в GitLab CE `/approvals`. GitLab API вызывается с фиксированного origin и с ограниченным по размеру ответом.
- Демонстрационная привязка: сервис проверяет bearer пользователя через каталог команд и сравнивает полученный ID с GITLAB_DEMO_SUBJECT. Для доступа к GitLab используется отдельный read-only токен из Docker secret. Этот режим предназначен для изолированного демо с тестовыми данными. Общая сессия Бобби не подходит для личных токенов. Персональный OAuth остаётся следующим этапом.
- Worker узнаёт инструменты через tools/list и отправляет вызовы через tools/call. Настройка GITLAB_MCP_URL по умолчанию пустая. Недоступный каталог GitLab не блокирует другие источники. Worker использует пользовательский bearer для GitLab MCP, ключ API Бобби туда не отправляется.
- Добавлены инструкции модели для рекомендаций и оценки навыков с опорой на документацию Авито, роль, практику команды, релевантные задачи и другие доступные источники. Навыки сотрудников и критерии оценки пока не заведены отдельным каталогом.

## Docker

compose.gitlab-demo.yml описывает отдельный проект bobby-gitlab-demo с именованными томами и портом 127.0.0.1:18929. Для браузера имя gitlab.local должно разрешаться в loopback. В стабильном окружении задаётся конкретный GITLAB_IMAGE. GitLab на Docker Desktop Windows используется для пробного запуска.

compose.gitlab-integration.yml — дополнение к compose.distributed.yml для изолированного тестового стека. Перед применением базового Compose задать отдельные порты, имена образов и тома или использовать отдельный Docker Engine. GITLAB_API_ORIGIN должен быть доступен из контейнера адаптера. Указать GITLAB_DEMO_SUBJECT и GITLAB_DEMO_TOKEN_PATH, файл токена хранить вне Git. Для сквозной проверки нужны тестовый проект и реальный read-only токен.

## Календарь и следующие шаги

С 10 ноября по 9 декабря 2026, МСК, будни 09:00–18:00. «Онбординг стажёра»: знакомство и обзор доступов, регулярный 1:1, цели и трекер прогресса, документы команды, Go и базы данных, итоговая сверка. «Доступность ментора»: окна вопросов, разбора ревью и 1:1. Время и события учебные. Источник содержания — локальная выдержка открытого чек-листа Авито.

Два календаря созданы в подключённом Google-аккаунте: «Бобби — онбординг стажёра (демо)» и «Бобби — доступность ментора (демо)». В первом проверено 13 событий, во втором — 9 экземпляров двух повторяющихся окон на период 10 ноября — 9 декабря 2026. События не рассылают приглашения другим участникам. Все даты и слоты учебные, содержание выводится из открытого чек-листа, а не из реального расписания Авито.

Добавлен отдельный calendar-integration MCP и Compose overlay. Инструмент календаря онбординга читает события в ограниченном диапазоне (не более 31 дня); инструмент ментора вызывает Google FreeBusy и возвращает только интервалы занятости. При ошибке FreeBusy доступность считается неизвестной. Оба работают только для привязанного демо-sub каталога команды. Токен Google обновляется через OAuth refresh token из Docker secret; клиентский ID и secret тоже читаются из файлов secret. В проекте Google Cloud `AcademyCalendarAPI` создан отдельный OAuth-клиент типа Desktop с областью `https://www.googleapis.com/auth/calendar.readonly`. После согласия владельца Google-аккаунта утилита `cmd/calendar-oauth-bootstrap` получила refresh token через локальный loopback callback, PKCE и `access_type=offline`. Реквизиты и токен сохранены только в `D:\HackChange\private` с ограниченным ACL, вне Git; в этом документе их значения не приводятся. Утилита не заменяет индивидуальный вход пользователей в Бобби. Источники OAuth/FreeBusy: https://developers.google.com/identity/protocols/oauth2/native-app и https://developers.google.com/workspace/calendar/api/v3/reference/freebusy/query.

Добавлены маршруты API `/v1/gitlab/reminders` и `/v1/calendar/reminders`. Они передают bearer текущей демо-сессии в соответствующий MCP, возвращают только его результат и не кешируют ответ. Интерфейс Бобби опрашивает их раз в минуту и показывает карточки открытых нечерновых MR и событий онбординга на ближайшие 24 часа. Дедупликация карточек действует в текущей вкладке; доставка по email/push и постоянное состояние подписок ещё не реализованы. Для GitLab стабильный ID меняется при обновлении MR, для календаря — при изменении времени события. Нельзя выдавать это за подтверждённую доставку приглашений или личное уведомление ментора.

Остаются личный OAuth GitLab и Google Calendar, постоянные подписки и доставка вне открытой вкладки. Рекомендации ещё нужно проверить на тестовом профиле стажёра и разных наборах доступных источников.

## Слияние

Конфликты в `answer.go`, `distributed_runtime.go` и `web.go` разрешены с сохранением истории диалога, нового MCP каталога команд в team-access, формы прав и опциональных GitLab/Calendar MCP. Для всех внешних MCP worker передаёт bearer пользователя без внутреннего API-ключа. Старые Jira-карточки отключены в чате по решению команды: остаются новые сохранённые уведомления стажёру и наставнику; старый HTTP/WebSocket API оставлен для совместимости. GitLab и Calendar карточки работают отдельно. Вторая ветка добавила миграции для истории и уведомлений, а также поля Jira identity в каталоге команды; их надо применить при развёртывании. Новые Dockerfile и Compose overlays независимы от базового Compose, но overlays задают URL сервисов как API, так и worker. `go test ./...` после разрешения конфликтов прошёл. Перед общим развёртыванием проверить обычный чат, формы прав, все маршруты уведомлений, GitLab и Calendar tools/list и tools/call, а также отказ при другом ID пользователя.

На живом локальном GitLab создан закрытый проект `root/bobby-team-directory-demo` (ID 2). Скрипт scripts/gitlab-demo-seed.ps1 запущен с `-ProjectID 2`: два явно перечисленных файла каталога команды, отдельные коммиты и два MR (готов к ревью и черновик, IID 1 и 2). Временный проектный токен записи после заполнения отозван и удалён. Для MCP создан отдельный проектный токен `read_api` с ролью Reporter и сроком 30 дней; он лежит в `D:\HackChange\private\gitlab-demo-read-token` вне репозитория с ограниченным ACL. Значение токена в спецификацию не заносится. Отдельный тестовый контейнер GitLab MCP слушает только `127.0.0.1:18930`; проверены каталог инструментов и вызов списка MR с демо-сессией стажёра. Общий worker ещё не перезапускали после слияния веток; сквозной тест объединённого стека остаётся перед развёртыванием.

Локальная проверка: `go test ./...` прошёл до и после слияния. Google Calendar-плагин подтвердил 13 событий онбординга и 9 экземпляров двух повторяющихся окон ментора. На живом GitLab MCP после обновления подтверждены 14 инструментов и ровно одно напоминание о нечерновом открытом MR (IID 1); черновик IID 2 исключён. После OAuth-согласия запущен отдельный контейнер `bobby-calendar-mcp-demo` на `127.0.0.1:18931` с секретами из `D:\HackChange\private`. Сквозной MCP-вызов от имени демо-стажёра подтвердил два инструмента, 13 событий онбординга и ответ FreeBusy для календаря ментора. Сквозной тест общего worker с объединённым кодом ещё не проводился.

## Развёртывание объединённого стека 11 ноября

Рабочая ветка и локальный master сведены к `6e8883e`. Демо-контейнеры GitLab MCP и Calendar MCP подключены к сети `avito-rag-distributed_default`. `compose.active-mcp.yml` задаёт адреса этих существующих контейнеров для API и worker; их секреты остаются в `D:\HackChange\private`. Объединённый образ `avito-rag-api:distributed` собран через `Dockerfile.offline`, затем API и worker перезапущены. При пересоздании демо-контейнеров их нужно снова подключить к сети либо развернуть через штатные Compose overlays.

Проверено после запуска: `/v1/deadline-notifications`, `/v1/gitlab/reminders` и `/v1/calendar/reminders` вернули HTTP 200; живой вопрос «Who is on my team?» завершился ответом worker. Тестовый GitLab MR и календарные события доступны через соответствующие MCP. Отдельную доставку уведомления о будущем Jira-дедлайне в этой проверке не имитировали.
