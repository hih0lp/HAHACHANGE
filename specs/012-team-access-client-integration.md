# SDD-012: связь двух Go-сервисов и чата Бобби

## Состав

`cmd/server` — API Бобби, асинхронные задания, чат и сценарий первой задачи. `cmd/team-access` — отдельный API профиля, каталога команды, прав и заявок по контракту SDD-013. Они соединяются через `TEAM_ACCESS_URL=http://team-access:8080` во внутренней сети Compose. PostgreSQL хранит оба набора данных; сервис доступа публикует события через outbox в Kafka topic `team-access-events`.

## Идентичность в чате

Пользователь входит на `/onboarding` под синтетической учётной записью. JWT хранится только в `sessionStorage` вкладки и передаётся Бобби в `Authorization` при создании задания. API Бобби вызывает `GET /v1/me`, каталог и `POST /v1/access/check` с этим JWT. Результат проверяется на совпадение ресурса и действия. Снимок профиля, ресурсов, прав и времени проверки сохраняется в `ai_jobs.team_context`, затем передаётся worker как данные для ответа. JWT не записывается в PostgreSQL/Kafka и не передаётся модели.

Без JWT чат отвечает на общие вопросы и не утверждает персональные права. Некорректный JWT не подменяется демо-пользователем. Состояние `missing` означает отсутствие grant только в прототипе; реальный Jira-доступ этим не определяется. Повторный вопрос получает новый снимок. Результаты не дают Бобби полномочий одобрять заявку: решение принимает отдельный пользователь-согласующий через сервис.

## Сценарий первой задачи

`POST /v1/scenarios/login` проксирует вход. `/v1/scenarios/*` использует проверенный JWT для профиля, ресурсов, проверки права и заявки. Состояние сценария хранится в `ai_scenarios` и не считает отправку заявки одобрением.

API Бобби читает `team-access-events` отдельной Kafka-группой. Уникальный `event_id` хранится в `ai_scenario_events`; повторная доставка не меняет состояние второй раз. Решение по связанной заявке помечает ожидающий сценарий `needs_refresh`. Следующий `GET /v1/scenarios/{id}` проверяет право через сервис с JWT пользователя, сохраняет новый шаг, а страница опрашивает сценарий раз в пять секунд. Само Kafka-событие не считается доказательством grant.

## Ограничения развёртывания

Адреса `127.0.0.1:18000` (Бобби) и `127.0.0.1:18080` (сервис доступа) предназначены для локального прототипа; HTTP не должен публиковаться за пределы localhost. Перед внешним доступом нужен TLS. Демо-cookie Бобби связывает историю чата с браузером, а не с JWT-пользователем; для многопользовательской системы понадобится заменить его на проверенную авторизацию и изолировать историю по `sub`.

## Проверка

`go test ./...`; `scripts/team-access-smoke.ps1` проходит профиль двух пользователей, каталог, pending, повторный запрос, изоляцию, approve, reject и grant. Отдельный запрос к `/v1/jobs` с JWT должен завершиться с `team_context` в PostgreSQL и ответом, который различает прототипные и реальные права.
