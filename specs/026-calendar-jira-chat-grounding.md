# SDD-026: Calendar, Jira dates, and readable answers

The intern asks about events and mentor availability in one selected mentor calendar. The calendar MCP exposes `calendar_mentor_events` for event details and `calendar_mentor_freebusy` for busy intervals, both using `CALENDAR_MENTOR_ID`. The older onboarding calendar ID is not used for reads or notifications. Relative dates are resolved in Europe/Moscow by the calendar MCP: `day=today` or `day=tomorrow` yields exact local-day bounds, while explicit ranges use RFC3339 timestamps. The model receives current Moscow date and time and chooses the MCP tool from its description. Calendar notifications use the same selected mentor calendar.

Jira issue details include due date and start date (`duedate` and this demo Jira's `customfield_10015`). For later questions about other fields, `jira_get_issue_fields` fetches all nonempty fields with their Jira display names. The agent must not infer dates from status or project documents. A missing description remains missing; summary is labelled as the task title. The verified team profile is included in the agent context for personalized answers. Recommendations still need separate source verification and coverage work before they can be considered complete.

The chat renders headings, lists, emphasis, and safe HTTPS links as DOM nodes for both new and restored answers. It never inserts model HTML. Existing task notifications retain their distinct amber cards. The model selects team, Jira, GitLab, and calendar MCP tools based on their descriptions and the request rather than keyword-triggered prefetch. If a required source is unavailable, the agent returns an explicit limitation instead of a fabricated personalized recommendation. The agent must not infer a person's skill from generic documentation. Full recommendations require the pending per-person GitLab MCP deployment.
