# SDD-055. Проверка источников в продолжении чата

Планировщик получает до четырёх последних обменов диалога для
разрешения ссылок и уточнений. Последний вопрос определяет действие.
Один маршрут выбора источников применяется к первому вопросу и к
продолжению. Отказ одного каталога MCP не блокирует вопрос к другому
сервису. Планировщик и модель не выполняют записи в учебные сервисы.

- Jira: личный список и карточку запрашивает сервер по JWT. Пояснение
  конкретной задачи строится из её текущей карточки. Обещание вызвать
  инструмент после ответа не выводится как итог.
- GitLab: список коммитов, diff, открытые merge requests и их апрув
  читаются разными вызовами. Проект сопоставляется со списком доступных
  проектов. При неоднозначности Бобби предлагает выбрать проект.
- Календарь: события наставника и компании имеют разные запросы.
  Ответ содержит границы реально проверенного периода. Для 1:1 Бобби
  показывает помеченные окна и сообщает об отсутствии данных о записи.
- Мессенджер: `list_my_groups` читает членство авторизованного
  пользователя, включая группы без сообщений. Тематический поиск
  запрашивает сообщения по теме и периоду до генерации резюме.
  Для явно указанной группы ответ сохраняет авторов, время
  и выдержки из найденных сообщений.
- Документация: уточнение может использовать самостоятельный запрос
  поиска, сформулированный по недавнему контексту. Сервер раскрывает
  ссылки только по меткам реально возвращённых фрагментов и только
  при наличии допустимого URL. Уточнение о README AvitoTech запрашивает
  точный путь в индексе. Если модель не подтверждает ответ ссылками
  после повторной попытки, Бобби показывает найденные источники.

При ошибке сервиса ответ отличает недоступность проверки от пустого
успешного результата. При обещании вызвать инструмент модель получает
одну повторную попытку с просьбой выполнить вызов в текущем ходе.

При `LLM_PLANNER_NO_THINK=true` запрос планирования к Qwen
в LM Studio использует `/no_think` и ограничивает длину JSON.
Параметры генерации ответа пользователю задаются отдельно.

Проверки: `go test ./...`. Регрессии включают извлечение diff по
следующему вопросу, точный интервал 1:1, отсутствие фиктивной записи
на встречу и разрешение ссылок только на найденные документы.
