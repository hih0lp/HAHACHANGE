# Задание второму агенту

Реализуй Go-сервис по `specs/007-team-access-contract.md`. Это окончательный контракт интеграции с бадди. Обрати внимание: resources возвращает объект `{resources:[...]}`, JWT имеет аудитории `ai-buddy` и `team-access`, профиль содержит `current_team_id` и `teams`.

Рабочая ветка: `codex/team-access`. Подготовленная отдельная рабочая копия: `/Users/mac/Documents/ChatGPT/Хахатон/avito-rag-team-access`. Перед началом получи последнюю версию контракта из `codex/distributed`; в рабочую копию могли не попасть поздние уточнения.

Твои файлы: `cmd/team-access/`, `internal/teamaccess/`, `migrations/team_access/`, тесты и документация сервиса. Общий Go-модуль можно расширить необходимыми зависимостями. Основной агент владеет `cmd/server/`, `internal/scenario/`, `internal/distributed/`, Compose и веб-интерфейсом. Эти файлы не меняй, чтобы избежать конфликтов. Подготовь отдельный Dockerfile сервиса; основной агент подключит его к Compose.

Рабочий сервис хранит данные в PostgreSQL и публикует Kafka-события через outbox. Никакого runtime mock mode, ответов из зашитых JSON или автоматического одобрения. Синтетические пользователи/ресурсы создаются seed-процедурой; пароль передаётся окружением и хешируется. Права меняются только через авторизованные операции; стажёр и согласующий — разные пользователи.

Приложи инструкцию окружения и запуска, миграции, автоматические проверки изоляции пользователей и жизненного цикла заявки, результаты тестов. Коммить и пушь свою ветку в `https://github.com/hih0lp/HAHACHANGE.git`. Не меняй main и не интегрируй самостоятельно ветку основного агента. Верни SHA коммита и список переменных окружения для подключения.
