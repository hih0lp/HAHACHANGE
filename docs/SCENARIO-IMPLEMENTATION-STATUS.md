# Состояние реализации SDD-008

Реализован первый участок: клиент SDD-007, вход через HTTP-сервис, проверка профиля, API создания/чтения/обновления сценария, PostgreSQL-снимок с владельцем и ревизией, проверка Jira-доступа, виджет подтверждённой заявки, сохранение её ID, повторная проверка и восстановление страницы после входа. Клиент не возвращает тестовые данные при недоступной зависимости.

Ещё не реализованы: вызов планировщика LLM для следующих этапов, выбор Jira-задачи внутри сценария, GitLab/MR, автоматическое применение событий Kafka к сценарию, UI согласующего (принадлежит сервису SDD-007), сквозной прогон с сервисом SDD-007 и тесты PostgreSQL-сохранения/конкуренции. Нельзя считать весь путь до PR готовым. Распределённая инфраструктура в этой ветке также требует живой проверки с PostgreSQL/Kafka.

Проверка 2026-11-10: `go test ./...` прошёл. `go test -coverpkg=./... -coverprofile=... ./...` прошёл, суммарное покрытие statements — 58.9%. Это ниже требований кейса и порога 90% в Dockerfile; Docker gate не пройден. Тесты HTTP используют локальные фикстуры исключительно в тестовом процессе; рабочий агент всегда обращается к TEAM_ACCESS_URL.

Настройка: в distributed Compose применить миграции 001 и 002; задать TEAM_ACCESS_URL, открыть `/onboarding`. Для существующего volume миграции применяются отдельно. JWT не сохраняется в PostgreSQL/localStorage; localStorage содержит только ID сценария, доступ к которому сервер повторно проверяет по профилю владельца.
