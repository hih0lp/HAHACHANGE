# Работа с avito-rag

- Перед любыми изменениями пользовательского интерфейса прочитай `specs/028-bobby-frontend-avito.md`. Это обязательный дизайн-код Бобби для разработчиков и агентов. В ревью укажи источники токенов и компонентов, приложи проверку состояний и размеров экрана. Несогласованные визуальные отступления не принимаются.

- Для каждой новой или изменённой функции агента и пользовательского сценария обновляй SDD-спецификацию в `specs/` до завершения работы.
- После правок запускай относящиеся к ним тесты и фиксируй результаты проверки.
- Коммить проверенные изменения в Git и отправляй коммиты на GitHub. Если авторизация GitHub недоступна, прямо сообщай, какие коммиты остались локальными.
- Не коммить `.env`, ключи и другие секреты; пример конфигурации держи в `.env.example`.
- Не представляй демо-роль, переданную клиентом, как производственную проверку прав. Перед масштабированием на несколько экземпляров API устраняй локальное состояние заданий и файловое хранилище действий в отдельном архитектурном изменении.
- Не додумывай сведения о внутренних процессах, людях и задачах. Если данных нет в доступных источниках или Jira, прямо сообщи, что они не найдены; не выдавай предположения, демо-данные или типовой процесс за установленный факт. Для каждого утверждения о задаче или регламенте указывай подтверждающий источник. На общие вопросы агент может отвечать собственными знаниями без обязательной ссылки, обозначая неопределённость там, где нет свежей проверки.
