# Как работает access token Бобби

Access token — временный JWT, по которому сервисы команды определяют пользователя и проверяют его права. Он нужен для доступа к профилю, ресурсам и формам заявок, а также для вызова инструментов команды из чата.

## Выдача и обновление

1. При открытии сайта браузер получает подписанную cookie сессии `ai_demo_session`.
2. Фронтенд вызывает `POST /v1/team-access/session`. Бэкенд определяет роль по cookie `buddy_demo_role` и входит в Team Access от имени первого стажёра, второго стажёра или наставника. Пароли демо-ролей берутся из серверной конфигурации.
3. Team Access возвращает `access_token`, тип `Bearer` и оставшийся срок в секундах (`expires_in`). Срок токена по умолчанию — один час. Его задаёт `TEAM_ACCESS_TOKEN_TTL_HOURS`.
4. Фронтенд держит токен в памяти страницы. При открытии сайта и затем каждые две минуты он повторно запрашивает токен через тот же маршрут. После перезагрузки страницы токен выдаётся заново.

## Использование

Фронтенд передаёт токен в HTTP-заголовке:

```http
Authorization: Bearer <access_token>
```

Team Access подписывает JWT по алгоритму RS256. При проверке сервис сверяет подпись, издателя, аудиторию и сроки действия, затем извлекает идентификатор пользователя (`sub`). Права на конкретный ресурс или действие проверяются в соответствующем сервисе.

Если вопрос в чате отправлен с токеном, API проверяет его через профиль Team Access. Для отложенной обработки токен временно хранится в Redis с TTL 15 минут. Воркер использует его для авторизованных вызовов сервисов команды. В промпт модели токен не передаётся.

## История чата

Сообщения хранятся в PostgreSQL. Маршрут `GET /v1/chat/history` выбирает последние 100 записей вопросов и ответов для сочетания идентификатора браузерной сессии и демо-роли. При обновлении JWT это сочетание сохраняется. Смена роли открывает отдельную историю, а удаление cookie начинает новую браузерную сессию.

Демо-роль выбирается в интерфейсе тестового стенда. Для рабочей установки с личными историями нужна идентификация пользователя через систему входа организации.
